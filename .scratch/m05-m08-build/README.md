# M05–M08 实施规格 — 考勤 / 事件与比分 / 统计 / 分组 / 阵容 + 前端骨架

Status: resolved

事实源：需求 v1.15（ATT/EVENT/LINEUP/GROUP、§7 权限、§8–§9、§11–§12）；design 01 §4.6–4.9、02 §6.5–6.8/§7.3–7.6、03 §4–§5、04 §5.12–5.21、05 §3.6–3.9/§3.14；`docs/rules/*`；路线图决策票 `.scratch/m05-m08-roadmap/issues/01`–`04`。

## Problem Statement

M01–M04 已让球队能建赛、报名、候补与递补，但一场比赛从“锁定”到“赛后”的核心链路仍然是断的：

- 球员到场后无法签到，管理员无法记录谁来了、谁没来、谁临时到场。
- 比赛中无法记录进球、乌龙、换人、黄红牌，也无法独立录入比分；比赛详情没有事件推导比分。
- 没有统计汇总，球员/球队页的出场、进球、助攻只能手工维护，分组自动分没有输入。
- 队内赛/训练赛无法把报名名单分成水平与位置均衡的两队，管理员只能手工分。
- 管理员无法排阵型、首发与替补；球员没有可查看的阵容。
- `frontend/` 尚不存在，C/B 两端都没有真实页面，以上能力即使有接口也无法被使用。

结果：报名结束后，球队仍然回到聊天群 + 表格手工运营，MVP 的“比赛日闭环”没有完成。

## Solution

按 `frontend-bootstrap → M05 ∥ M06 → stats → M08 → M07` 的顺序交付六条纵向切片，每条后端先行、页面随模块、以一条 Playwright 黄金路径收口：

1. **frontend-bootstrap**：C/B 双壳层、登录、各一屏真实只读数据；不碰业务页面。
2. **M05 考勤**：自助签到、管理员标记/修正、临时到场、赛后 +6h 自动缺勤、B03/C03 签到。
3. **M06 事件与比分**：事件时间线、类型专属字段、比分独立录入、事件推导比分、B04/C03 事件 Tab。
4. **stats**：Quartz 每 10 分钟汇总出场/进球/助攻，写汇总表与 Redis 缓存；M08 与球队页消费。
5. **M08 分组**：逐位置蛇形 + 局部搜索 + 随机因子；生成/调整/保存/清除；B06/C03 分组 Tab；随后回填 M06 分组校验。
6. **M07 阵容**：8 套预置阵型 + 自定义模板、首发 8 人 + 替补、队内/训练赛分组约束、版本冲突；B05。

每个模块的完成标准沿用路线图票 01：**后端门**（05 契约全部实现、`mvn verify` 全绿、空库 Flyway 幂等、ArchUnit 通过）+ **页面门**（02 对应页面交付、每模块一条 Playwright 黄金路径）。

## User Stories

### 前端骨架

1. 作为球员，我想用手机号和密码登录 C 端，以便查看赛程与参与比赛。
2. 作为球员，我想在登录后看到移动端顶部导航与底部栏，以便在赛程、我的报名等页面之间切换。

6. 作为管理员，我想用手机号和密码登录 B 端，以便管理比赛、报名、考勤与战术。

9. 作为开发者，我想 `pnpm -r build/typecheck/test` 全绿，以便前端骨架可被后续模块安全复用。
10. 作为开发者，我想 C/B 各有一条 Playwright 冒烟无 console error，以便登录、权限与请求封装四条链路被验证。

## Implementation Decisions

### 交付顺序与阻塞边

- 顺序固定：**frontend-bootstrap → M05 ∥ M06 → stats → M08 → M07**；M06 的分组校验回填排在 M08 之后。
- `frontend-bootstrap` 阻塞所有模块页面票；后端模块票可与它并行。
- `stats` 阻塞 M08；`M08` 阻塞 M07 与 M06 回填。
- 每个模块一张后端票 + 一张页面票（可合并为同一模块的两条阻塞子票），页面票依赖 frontend-bootstrap 与本模块后端票。

### 跨模块契约（内部接口，不改 05 对外契约）

- 扩展比赛只读快照：`type`、`season`、`ourSide`、`includeGuests`、`statusUpdatedAt`。M05 需要 `statusUpdatedAt` 计算提前结束后的 +6h；M07 需要 `ourSide/type`；M08 需要 `type/season/includeGuests`。
- 比赛读端口新增：赛季已结束且未取消的球队比赛计数（M08 出场率分母）、按比赛锁定比赛行（分组写串行化）、按球队+赛季扫描已结束比赛（stats 汇总）。
- 报名读端口新增：本场 CONFIRMED 报名名单（playerId + registrationType），供 M05/M06/M07/M08 共用；不改变现有分页名单接口。
- 新增考勤读端口、事件读端口（供 stats 汇总），新增分组读端口与已保存分组快照（路线图票 03 已定），适配器放各业务域 application。
- 新增分组配置端口：`manualWeight/autoWeight/appearanceWeight/goalWeight/assistWeight/minAppearances`，默认 70/30/50/25/25/3；缺失或非法按 M08 规格回退。M11 的设置管理页不在本规格内，只读取既有 `system_setting` 种子/默认值。
- 账号 ACTIVE 过滤复用现有账号读端口；球员位置/星级/类型/号码复用现有球员读端口。
- 业务域不得直接访问他域 Mapper/表；`event` 只经 contracts 分组端口读已保存分组；`stats` 只读依赖各域端口，仅 `query` 与 `grouping` 可依赖 stats 只读接口。

### M05 考勤

- 接口沿用 05 ATT-01…ATT-06；权限码已存在，不新增。
- 签到窗口：开赛前 4 小时至比赛当天 23:59（`Asia/Shanghai` 推导后转 UTC）；由窗口驱动，不按比赛状态开关；`CANCELLED/POSTPONED` 返回 40905。
- 自助签到仅限本场 CONFIRMED 报名；同一比赛同一球员只有一条考勤（`UK(match_id,player_id)`）。
- 自助签到是幂等的：已有 SELF 记录返回原记录；已有 ADMIN/SYSTEM 记录不覆盖，直接返回原记录——管理员标记优先。
- 管理员标记只接受 `PRESENT/ABSENT`，来源 ADMIN；临时到场只走 ATT-06，来源 ADMIN。
- 临时到场要求球员属于本队、未注销，且本场没有 CONFIRMED 报名；已有确认报名的球员应走签到/标记，不重复建临时记录。临时到场不占名额、计入出场、不计缺勤。
- 缺勤任务：Quartz 每 10 分钟扫描 `FINISHED` 且实际结束 +6h 已到的比赛；实际结束时间优先 `status_updated_at`（提前结束），否则 `end_at`；跳过 `CANCELLED/POSTPONED`；对无考勤记录的 CONFIRMED 报名写 `ABSENT/SYSTEM`；已有记录不覆盖；重复执行幂等。
- 可见性：ATT-03/04 需要 `attendance:view:any`（正式球员/管理员）；外挂只有 ATT-02 本人。
- REG-04 的 `attendance` 字段由 M05 填充，未报名/无记录仍为 null。
- 管理员标记/补录写审计（动作键 `ATTENDANCE_MARK`/`ATTENDANCE_TEMP`，精确枚举由 M10 统一）。
- 页面：B03 报名/考勤（比赛选择器、统计卡、正式/候补/外挂分栏、来源、标记/补录/移除）；C03 本人报名卡与签到按钮、全队考勤只读。

### M06 事件与比分

- 接口沿用 05 EVT-01…EVT-07；事件实体含 `is_deleted`、`deleted_at/deleted_by`、`version`，事件历史独立留存。
- 字段规则：`minute` 1–120、`half` 必填；`GOAL` 可带助攻与点球；`OWN_GOAL` 不带助攻/点球；`SUBSTITUTION` 必须 `inPlayerId/outPlayerId` 且不同、`playerId` 为空；非换人 `playerId` 必填、换上/换下为空。所有规则应用层强校验，数据库无 CHECK。
- 权限：球员可创建/修改自己作为主体的事件，窗口为比赛结束 +24h；换人仅管理员；删除仅管理员；管理员不受时间限制。队内/训练赛球员可为主客任意球员创建事件（受控例外）。对外比赛球员录入时球队锁定本人所属队。
- 选人前置：球员/助攻/换上/换下须为本场 CONFIRMED 且账号 ACTIVE 的报名；M06 第一阶段只校验报名；M08 落地后经 contracts 只读端口读取**已保存**分组（`saved_at` 非空），主队=A 组、客队=B 组，草稿不约束，不匹配返回 42203；管理员不豁免；PATCH 按合并后的有效事件校验。
- 推导比分：仅统计未删除事件；GOAL 记事件所属队，OWN_GOAL 记对方；EVT-01 返回 `derivedScore`，比赛详情 `MatchDetail.derivedScore` 由 null 改为推导值。
- 时间线排序：半场升序 → 分钟升序 → 同分钟 GOAL/OWN_GOAL 优先 → id 升序。
- 存储比分：与事件独立，写 `team_match.score_home/score_away`，使用 `version` 乐观锁；与推导值不一致只提示不阻断。
- 事件创建/修改/删除写 `event_history`（CREATE/UPDATE/DELETE，前后 JSON、操作人、requestId）；同时写审计（`EVENT_CREATE/EVENT_UPDATE/EVENT_DELETE`，精确枚举由 M10 统一）。
- 页面：B04 事件/比分（比赛选择器、比分编辑器、时间线、录入/编辑弹窗、42203 行内提示）；C03 事件 Tab（统计卡、时间线、录入入口、按权限禁用）。

### stats

- Quartz 每 10 分钟全量重算本赛季（赛季取比赛赛季字段，空则开赛年份）未取消比赛的考勤与事件；按球员汇总：
  - 出场：`PRESENT` 或 `TEMP_PRESENT`；
  - 进球：`GOAL` 且未删除；`OWN_GOAL` 不计个人进球；
  - 助攻：`GOAL` 的 `assist_player_id` 且未删除；
  - 取消比赛不计任何统计。
- 按 `UK(team_id,player_id,season)` 批量 upsert；失败保留上一次结果并告警；任务按主键幂等。
- 汇总后刷新 Redis 统计缓存；球队页/球员页缓存未命中回源汇总表；允许最多 10 分钟延迟。
- 读接口沿用 STA-01；分组经 stats 只读接口 `seasonStats(teamId, season)` 取汇总，不直读汇总表。
- 汇总任务通过各域只读端口取考勤/事件/比赛/球员，不直读业务表。Quartz 使用 `QuartzJobBean` + Trigger，禁止 `@Scheduled`。

### M08 分组

- 接口沿用 05 GRP-01…GRP-06；候选、评分、分配、搜索、警告、指纹、持久化按路线图票 04 的 Answer 实现，关键口径：
  - 候选 = 本场 CONFIRMED、账号 ACTIVE、属于本队、按 `includeGuests` 过滤；赛季取比赛赛季。
  - `manual = player.skill`；`auto = 1 + 4 × (0.50×出场率 + 0.25×进球归一 + 0.25×助攻归一)`；出场率分母为同赛季 `FINISHED` 场次（0 按 1）；进球/助攻在候选池 min-max 锚 0 归一；`appearances = 0` 或 `< minAppearances` 时 `final = manual`，否则 70/30；先舍入再排序/落库。
  - 分配：GK→DF→MF→FW 逐位置；位置内 `final + (rand-0.5)×1.2` 降序、`A,B,B,A` 蛇形、每位置随机起始队；人数修平 → 门将修复 → 局部搜索。
  - 搜索目标字典序 `[缺门将, 人数差>1, 总分差, 外场位置差]`；best-improvement 跨队交换；无改进或 `max(20,n²)` 轮停止。
  - 随机性：`SecureRandom` 取种子、`SplittableRandom` 驱动、种子不落库、DEBUG 记录；不做随机重启。
  - 警告固定顺序：人数差 → GK 0/1/≥2 → 各外场位置人数/位置差；永不阻断。
  - 指纹：候选 playerId 升序逗号连接后 SHA-256 小写十六进制；GRP-04 锁定候选池（当前指纹 ≠ 存储指纹 → 40911）；GRP-05 保存保留生成时指纹；名单变化或警告需 confirm。
  - 行级语义：清除物理删除两表行；生成已有行 UPDATE 并物理替换球员集合；调整原地更新 team；保存后调整需 confirm 并回到草稿（`saved_at=NULL`）。写操作锁比赛行串行化。
  - 错误码：40905 状态、42201 业务规则、42202 confirm、40911 指纹、40001 结构。
- M08 完成后回填 M06 四个写接口的分组校验与测试。
- 页面：B06（比赛选择器、生成/重新生成、清除、A/B 两列、总分差、位置分布、警告、报名两列、未分组/不参与、拖拽/点选、保存）；C03 分组 Tab 只读。

### M07 阵容

- 接口沿用 05 LIN-01…LIN-08；权限码已存在。
- 模板：8 套预置（Flyway V4 已种子，64 槽位）；自定义模板为复制预置并命名；预置不可改/删；自定义可重命名/软删除；即使被阵容引用也允许删除，历史阵容仍可按 `formation_template_id` 读取已删除模板。
- 阵容：`UK(match_id,side)`、`version` 乐观锁；我方首发 8 人且每槽 `playerId` 必填；对手方允许空槽位、不录入球员；替补默认取本场可排且未首发者，可显式加入/移出并持久化。
- 可排名单：队内/训练赛存在已保存分组时，HOME=A 组、AWAY=B 组；首发/替补只能来自对应分组 ∩ 本场 CONFIRMED ∩ 账号 ACTIVE；跨队/已取消/已注销返回 42201；无已保存分组时来自本场确认报名；对外对手方仅阵型与空槽位。

## Testing Decisions

### 好测试的标准

- 只断言外部行为：HTTP 状态、envelope `code/message/data`、数据库副作用、审计 Outbox；不断言私有方法、Mapper 调用次数或实现结构。
- 每个测试一个行为，命名描述业务规则；用固定的比赛/球员/报名数据构造场景；时间相关规则注入固定 `Clock`。
- 失败必须能定位到契约或规则，不靠日志猜测。
- 不 mock 业务域内部；跨域用真实适配器或既有契约端口。
