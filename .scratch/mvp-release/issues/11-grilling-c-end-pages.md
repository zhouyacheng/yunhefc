# 11 — C 端公开页面与访客体验

Type: grilling
Status: resolved
Blocked by: 01, 07, 09

## Question

基于交付缺口、通知矩阵与列表契约，确定 C 端首批页面：

- 首页（下一场比赛、报名入口、报名/外挂/候补队列、近期赛程）、球队页、比赛详情、个人中心（资料 / 通知 / 我的报名）、登录注册。
- 访客可见范围与登录引导（AUTH-07）；明确哪些内容需要登录。
- 数据来源：05 §3.15 明确首页不提供聚合接口，用 `MAT-02?scope=upcoming&pageSize=3` + `GET /c/me`；球队页用 `PLR-01 + STA-01`。
- 通知入口、未读角标与已读交互（依赖 07）；赛程筛选/分页（依赖 09）。
- 加载中、失败、空数据状态与验收点。

事实指针：需求 §4.1 / §6.3、AUTH-07、02 §4–§7、05 §3.15、`frontend/apps/web` 现状、07 / 09 答案。

## Answer

决策日期 2026-11-11。四项关键取舍：公开页优先、C06 迁 `/profile`、C03 维持概览内含报名、头像随 OSS 批次。

### 1. 批次划分

**C-A（首批 C 端公开页）**
- C01 首页、C04 球队、C05 登录/注册（补注册、找回密码、邀请上下文；登录已有）、C06 个人中心（身份卡、资料编辑、通知、我的报名、账号安全）、C07 邀请落地、C09 403/404。
- 全局：底部四 Tab（首页/赛程/球队/我的，PQ-01）；C06 路由迁 `/profile`，`/account` 重定向；未知路由与 C03 不存在的比赛进 404。
- C02 已存在；完整筛选/搜索/URL 由 M12 批次（09 号票）落地，不并入本批。

**C-B（后续 C 端互动）**
- C03 补齐：报名/取消、全队名单与考勤、邀请队友、分享、管理员状态下拉（MAT-12），结构按「概览内含报名」。
- C08 微信授权回调、C05 微信授权入口、C06 微信绑定状态展示。

### 2. 访客可见范围（需求 AUTH-07）

- 公开：C01、C02、C03 概览/事件、C04 公开字段、C05、C07、C09。
- 需登录：C06、C03 报名操作、签到、我的报名、通知、接受邀请。
- C03 报名区：访客 → 登录引导；待审核 → 只读提示；外挂 → 仅本人；正式/管理员 → 全队。阵容/分组 Tab 对访客、待审核、外挂不可见。
- 访客首屏只读前端会话状态，`GET /c/me` 仅登录态调用（`ensureLoaded` 静默 401），不产生 console error。

### 3. 页面决策

**C01 首页**
- 单次 `MAT-02?scope=upcoming&sort=startAt:asc&pageSize=3`：Hero 取第 1 条，近期赛程取同 3 条；不新增聚合接口。
- 报名 CTA：访客 → 登录；待审核 → 提示；已报名 → 查看详情；未满 → REG-01 直接报名（幂等键，成功后刷新）；正式满 → 候补；外挂满 → 拒绝并说明；截止/锁定/延期/取消 → 禁用并说明。
- 无下一场显示「暂无待进行比赛」+ 去赛程，不回退历史；球队火力仅二期占位。

**C04 球队**
- `PLR-01`（每组默认 10，展开用 `all=true`）+ `STA-01` 按 `playerId` 合并；组顺序前锋/中场/后卫/门将；展示头像、姓名、号码、位置、星级、地区、出场、进球、助攻；无手机号、无外挂、无详情页。

**C05 登录/注册**
- Tab 登录/注册；登录沿用现有；注册字段手机号/验证码/密码/姓名/主位置，`inviteToken` 从 query 透传；找回密码走 AUTH-06；展示限流与错误文案。
- 注册成功展示待审核提示并按 `redirect` 白名单跳转；邀请链接进入时展示邀请上下文。
- 微信授权入口不在本批，随 C08；开发/测试可用短信 mock，生产真实短信是上线门槛（14）。

**C06 个人中心**
- 路由 `/profile`（需登录），`/account` 重定向。
- 身份卡 + 资料编辑（姓名/地区/主副位置，PLR-03；头像只读）。
- 通知：NTF-01 分页「加载更多」、未读筛选、单条/全部已读、按关联跳转；NTF-02 60s 轮询 + `visibilitychange` + 路由切换刷新；Tabbar「我的」显示角标；未登录不轮询、401 静默。
- 我的报名：REG-03 `active/history` 两组，默认进行中。
- 账号与安全：找回密码入口与退出；微信绑定状态随 C-B（契约见票 21）。
- 待审核横幅；加载/失败/空态齐备。

**C07 邀请落地**
- `INV-01` 判定：不存在 → 404；过期/撤销/用尽 → 失效说明；有效 → 展示类型、球队/比赛、邀请人、有效期与剩余次数。
- 加入：访客 → 登录/注册（带 `redirect` 与 `inviteToken`）；已登录 → INV-02；已是成员 → 提示；比赛邀请接受后跳比赛详情，不自动报名、不改变账号状态。

**C09 错误页**
- `/403`、`/404` 独立页面；403 说明权限并提供返回首页/切换账号，404 提供返回上一页/首页；通配路由改为 `/404`；C03 40401 与邀请不存在统一进 404。

### 4. C03 结构与后续补齐

- 维持 4 个 Tab：概览、事件、阵容、分组；不恢复独立「报名」Tab。
- 概览合并：报名概况 + 本人报名卡（状态、进度、报名/取消/签到及禁用原因）+ 名单与考勤（正式/管理员全队，外挂本人）+ 作废横幅；管理员移除跳 B03。
- C-B 补齐分享、邀请队友、管理员状态下拉与 404 分支。

### 5. 批次顺序与依赖（交 18 号票）

- C-A 的 C06 通知要求 M09 的 NTF-01~04 同批或先行。
- C-A 的 C01 报名依赖 REG-01，取消入口在 C-B 的 C03；两批须在上线前相邻交付，避免半个报名闭环。
- C08 与 C05 微信入口依赖 14 号票；C03 管理员状态入口与 20 号票协调；C06 微信绑定状态依赖票 21。

### 6. 验收映射

- C-A：AUTH-02/03/06 与需求 AUTH-07（未登录访客；非接口 ID）、PLAYER-05/07（资料）、TEAM-01~05、NOTIFY-01/03/05（配 M09）、REG-03、INVITE-01~05、LIST-05（相关页）、C09 体验。
- C-B：NOTIFY-02/MATCH-13 分享、REG-01/02 的 C03 取消闭环、MATCH-12 C03 状态入口、AUTH-03 微信登录。
- 头像上传验收随 OSS 批次；C09 无独立验收编号。
- 每页一条 Playwright 黄金路径，清单交 19 号票：访客首页→登录引导、球队分组/展开、注册→待审核、邀请接受、通知已读→角标归零、403/404。
