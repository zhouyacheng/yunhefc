### 2. 关键决策

1. **后端先行**：共享后端（M09/M12/M13/wechatBound）只在 B1 做一次；B2 与 B3 分属 admin/web，可并行，避免 M13 双端重复与两条页面线串行。
2. **单次正式上线**：批次是内部里程碑；B1 起可用生产 ECS 做 RC 部署验证，但不对外；C-A + C-B 相邻交付、真实短信/微信/OSS 验收通过后一次 cutover。避免 11 号票指出的「半个报名闭环」。
3. **批内顺序**：B1 的 M13 先于 M10 导出（复用 `OssGateway`）；B0 为 01→02→03；页面批先 shell 后页面。
4. **外部任务并行启动**：ECS/RDS/DNS/证书/ACR 在 B0 前；RAM/Bucket 在 M13 联调前；短信/微信在 B4 真实验收前。代码侧 dev/test 全 mock，prod fail-fast，外部延期不阻塞 B1–B3。
5. **交接格式**：每批 `README.md` + 一票一文件，沿用 `m05-m08-build`；每票单独会话、票间 `/clear`；完成门沿用后端门 + 页面门。

- M13 头像签名读同时影响 B07/C04/C06，只能在 B1 改一次。
- dashboard 前后端成对移除，否则登录落 403。
- 报名闭环跨 B3/B4，RC 阶段不得公告上线。
