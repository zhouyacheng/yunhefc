# 20 — B02 比赛管理交付深度

Type: grilling
Status: resolved
Blocked by: —

## Question

基于 01 盘点 §8.3 第 5 项，确定 B02 比赛管理页的首批交付深度：

- 维持现状（列表 + status 筛选 + 分页），还是补齐创建/编辑/状态重置/延期/重新排期/取消 UI？
- 若补齐，哪些操作进首批；哪些可由 C03 的 MAT-12 管理员状态下拉覆盖（需求 19h 允许在比赛详情直接改状态），避免两处重复。
- 前端复用哪些校验：开赛晚于当天 10:00、时长 2–4 小时、名额不得低于已确认人数、终态不可编辑、POSTPONED 只能走重新排期。
- 后端 MAT-04~08/11/12 已就绪，预计无新接口；如发现缺口是否补。
- 验收方式：哪些操作需要 Playwright，哪些接受人工演示。

事实指针：01 §4.2/§8.3、02 §6.4、05 §3.4、`frontend/apps/admin/src/pages/MatchesPage.vue`、C03 状态入口（11 号票）。

## Answer

- **交付深度：首批全量补齐 B02**，按 02 §6.4 一次交付，不分批缩水。列表加「操作」列；创建弹窗（MAT-04）、编辑弹窗（MAT-05）、状态下拉（普通状态 MAT-06）、延期弹窗（MAT-07）、重新排期弹窗（MAT-11）、取消二次确认（MAT-08）。
- **状态语义**：下拉展示全部状态；POSTPONED / CANCELLED 分别进入延期 / 取消流程（MAT-06 服务端本就拒绝二者）；普通状态直接重置并停自动流转；终态不可编辑，可经状态重置恢复。
- **入口归属：B02 独占**。管理员状态操作全部在 B02；C03 的 MAT-12 状态下拉仍按 11 号票留到 C-B，首批不实现，避免双入口与重复测试。
- **后端：无新接口**。MAT-04~08/11 已就绪，`Match*IT` 覆盖权限、幂等、版本冲突与异常状态；实施中若发现契约缺口，按 05 既有 ID 补齐并同步 04/05，不新增接口编号。
- **前端校验：抽 `frontend/packages/shared/src/match.ts` 纯函数**并补 Vitest —— 开始时间晚于当天 10:00、时长 2–4 小时、正式/外挂名额不低于已确认人数、终态不可编辑、POSTPONED 仅可重排、赛季四位年份。页面复用这些函数做预校验；后端 `MatchTimeRules` / `MatchStatusMachine` / 名额校验仍是权威兜底。
- **请求口径**：编辑/状态操作前用 MAT-10 取权威详情与 `version`；写请求带 `Idempotency-Key`（复用 `newIdempotencyKey`）与 `version`；成功后刷新 MAT-09。
- **权限**：页面入口维持 `match:view:any`；创建、编辑/延期/重排、状态重置/取消分别按 `match:create:any`、`match:edit:any`、`match:status:any` 控制按钮与操作列显隐，后端 `@PreAuthorize` 兜底。
- **验收**：`frontend/e2e/admin.spec.ts` 一条黄金路径 创建→编辑→延期→重新排期→取消；权限、幂等、版本冲突、非法状态由既有后端 IT 覆盖；需人工演示的项并入 19 号票检查单。admin 页面不新增单测门槛。
- **文档影响**：02 §6.4 已覆盖本范围，05/04 无契约变更，本次不改设计文档。
