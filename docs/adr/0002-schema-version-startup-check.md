# ADR 0002：后端 prod 启动时校验数据库 schema 版本

状态：已接受（2026-11-22）

生产库曾停在 V8 而镜像已是 V13，手机号登录返回 500（2026-11-20）。人工 `flyway info` 门禁写在 RUNBOOK 里，仍被跳过。决定：后端在 prod 启动时比对 `flyway_schema_history` 的最高成功版本与代码期望版本，库落后则 fail-fast，库超前（回滚旧镜像）放行。

## 放弃的备选

| 备选 | 放弃原因 |
|---|---|
| 仅保留 RUNBOOK 人工门禁 | 已失效一次；事后才发现，接口在线上返回 500 |
| `release.sh` 切 `current` 前查库 | 需要在 ECS 上引入 mysql client 或额外镜像，破坏「发布链路不访问 Docker Hub」的约束 |
| 应用启动后仅告警不拦截 | 不一致时业务查询仍会 500，告警无法阻止流量进入 |

## 后果

- 库落后时部署以「readiness 未通过」失败，`current` 已切到新版本，需显式 `release.sh --rollback` 或补迁移后重试；与现有 readiness 失败路径一致。
- 迁移与发版的顺序由「靠人记」变为「不迁移就发不出去」。
- 回滚不受影响：只拦「库落后」，不拦「库超前」。
