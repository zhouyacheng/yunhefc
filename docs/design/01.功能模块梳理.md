# 云河FC 功能模块梳理

- 文档版本：v0.12（第四轮复审修正）
- 编写日期：2026-11-09
- 审核日期：2026-11-09
- 依据材料：`docs/云河FC-需求文档.md`（v1.15）、`prototype/`（静态可交互原型）
- 文档范围：功能层面的模块划分、模块关系与核心业务流程；不包含技术选型、数据库、接口或代码设计

## 1. 文档说明

### 1.1 目的

把需求文档中的功能条目整理为可讨论、可分工的模块，明确每个模块的职责边界、依赖关系和核心流程，为后续页面设计、领域模型与接口设计提供共同语言。

### 1.2 依据与边界

- 功能来源以需求文档为准，模块条目均可回溯到需求编号（AUTH/RBAC/PLAYER/TEAM/MATCH/REG/ATT/EVENT/LINEUP/GROUP/NOTIFY/INVITE/CONFIG/LIST）。
- 原型只作为实现参照，用于确认交互与数据范围，不作为新增需求依据。
- 原型专属能力（演示身份切换、重置数据、球队火力预览等）不进入功能需求。
- 本期只服务云河FC 单队；多队、平台化、独立赛事积分榜明确不做。

### 1.3 读者

产品、设计、开发、测试；也作为需求评审的讨论底稿。

## 2. 产品范围与角色

### 2.1 范围

| 范围 | 内容 |
|---|---|
| MVP | 账号与权限、球员档案、球队页、比赛、报名与候补、考勤、事件与比分、阵容、队内分组、通知、邀请、管理后台、列表检索分页 |
| 二期 | 排行榜/身价、AI 天气、账本、动态、相册视频、投票、公众号、资产、荣誉、主页统计、数据提醒、Excel 导入、9/11 人制 |
| 明确不做 | 多队入驻、平台超管、跨队隔离、9/11 人制 UI、独立赛事/积分榜、错题本 |

### 2.2 角色与状态

| 角色/状态 | 说明 |
|---|---|
| 访客 | 未登录；仅浏览公开内容 |
| 外挂 | 非正式队员；可报名、签到、看自己的数据；不可看全队、阵容、分组，不可录事件 |
| 正式球员 | 可看全队报名/考勤、战术/阵容/分组；可录改自己的事件 |
| 管理员 | 拥有全部权限，且必须同时具备正式球员角色 |
| 自定义角色 | MVP 支持角色 CRUD；权限取多角色并集 |
| 账号状态 | 待审核 / 正常 / 注销；待审核仅浏览与改资料，注销不可登录 |

## 4. 模块划分

模块采用“业务域模块 + 支撑模块 + 展现层 + 二期边界”的结构。模块边界按业务能力与实体划分，不按现有原型脚本机械拆分。

### 4.1 模块总览

| 编号 | 模块 | 类型 | 一句话职责 |
|---|---|---|---|
| M01 | 账号与权限 | 业务域 | 谁可以进入系统、以什么身份、能做什么 |
| M02 | 球员档案 | 业务域 | 维护球队成员的身份信息与展示数据 |
| M03 | 比赛管理 | 业务域 | 创建与维护比赛，驱动比赛状态 |
| M04 | 报名与候补 | 业务域 | 管理参赛名额、候补队列与递补 |
| M05 | 考勤与签到 | 业务域 | 记录到场、缺勤与临时到场 |
| M06 | 事件与比分 | 业务域 | 记录比赛过程并形成比分与统计来源 |
| M07 | 阵容与战术 | 业务域 | 管理双方阵型、首发与替补 |
| M08 | 队内分组 | 业务域 | 按水平与位置把队内赛分成两队 |
| M09 | 通知 | 支撑 | 把关键业务变化触达相关球员 |
| M10 | 审计日志 | 支撑 | 记录关键写操作及前后快照 |
| M11 | 系统配置 | 支撑 | 管理跨比赛的默认参数与分组权重 |
| M12 | 检索与分页 | 支撑 | 统一列表筛选、排序与分页约定 |
| M13 | 公开站点与个人中心 | 展现 | 组合各模块读能力，面向球员和访客 |
| M14 | 二期能力 | 边界 | 明确本期不设计的能力范围 |

### 4.2 M01 账号与权限

**职责**：账号生命周期、身份认证、授权与邀请。

**关键功能**

- 手机号 + 密码注册/登录；密码 8–64 位，含字母和数字（AUTH-01）。
- 短信验证码用于注册、重置密码、绑定手机；开发环境固定验证码（AUTH-02）。
- 微信内网页授权；微信外使用手机号密码（AUTH-03）。
- 注册方式：自助注册（待审核）、邀请注册（入队免审）、比赛邀请（只引导，不改变账号状态）（AUTH-04、INVITE-01/02）。
- 账号状态：待审核/正常/注销；待审核仅浏览与改资料；注销不可登录、历史保留（AUTH-05、RBAC-07）。
- 密码重置与手机号换绑，管理员后台换绑留痕（AUTH-06）。
- 未登录访客可浏览公开内容，报名时引导登录/注册（AUTH-07）。
- 完整 RBAC：权限点、多角色并集、默认角色、角色 CRUD、默认角色与最后管理员保护（RBAC-01~06）。
- 邀请链接：入队/比赛两类；默认 7 天有效、默认不限使用次数（创建时可设上限）、记录邀请人、可撤销/过期（INVITE-01~05、DQ-03）。
- 入队邀请注册完全免审，直接为正常状态；滥用时由管理员注销账号（INVITE-01、DQ-04）。
- 微信解绑仅管理员可在后台操作，用户重新授权绑定，全程留痕（DQ-05）。
- 邀请管理权限：管理员可创建/撤销入队与比赛邀请（`invite:manage:any`）；正式球员仅可创建比赛邀请（`invite:create:match`，DX-03）。需求 §6.1/§7 已包含权限点 `invite:create:match` 并修订权限矩阵。

**主要实体**：用户、角色、权限点、邀请链接。

**依赖**：球员档案（注册建档）；通知、审计经领域事件。

**原型对应**：`login.html`、`profile.html`、后台“角色权限”；邀请、微信授权、找回/换绑未实现。

### 4.3 M02 球员档案

**职责**：维护球队成员资料、身份类型与公开展示数据。

**关键功能**

- 档案字段：姓名、球衣号码、主/副位置、地区、头像、星级（PLAYER-01/02/05/06）。
- 身份：外挂/正式互斥；管理员叠加正式；外挂转正；账号注销（PLAYER-03/04、§8.6）。
- 自助资料：姓名、地区、主副位置、头像；号码与星级由管理员维护（PLAYER-07）；正式球员号码在球队内唯一。
- 账号注销：不可登录，不进入球队页和报名名单，球员档案与历史数据保留（PLAYER-04、§8.4）。
- 球队页展示：仅正式且正常状态；按前锋/中场/后卫/门将分组，组内出场降序 → 号码升序；每组默认前 10 可展开；出场/进球/助攻来自统计汇总，允许最多 10 分钟延迟（TEAM-01~05）。

**主要实体**：球员档案、用户。

**依赖**：账号状态与角色；被报名、阵容、分组、事件、统计引用。

**原型对应**：`team.html`、`profile.html`、后台“球员”；完整。

### 4.4 M03 比赛管理

**职责**：创建与维护比赛，维护比赛状态与赛程信息。

**关键功能**

- 创建/编辑：默认队内赛、橙队/兰队、名称“橙队VS兰队”、场地聚龙足球场、比分 0:0；开始与结束相差 2–4 小时（MATCH-01/16）。
- 类型：正式比赛、队内赛、训练赛、友谊赛；本期 8 人制（MATCH-02/03）。
- 状态机：报名中 → 报名截止 → 锁定 → 进行中 → 已结束；分支已延期、已取消；自动流转 + 管理员手动覆盖（MATCH-04/05/06）。
- 时间：开赛必须晚于当天 10:00（P-08）；报名截止为开赛当天 00:00，锁定为当天 10:00，独立校验（MATCH-04、§8.10）。
- 延期：保留报名，按新时间重算截止/锁定，状态置为已延期；管理员重新排期后回报名中（MATCH-07，P-02 已确认）。
- 取消：报名记录保留但作废，通知，不计缺勤（MATCH-08）。
- 轻量赛事字段：赛事名称、赛季（四位年份）、轮次均为可选（MATCH-10）。
- 场次编号：赛季第 N 场 + 累计第 N 场，自动递增（MATCH-15）。
- 我方主/客：创建时显式选择；未选择时按队名是否包含“云河FC”推断；创建后不可改（MATCH-04、DQ-09、P-04）。
- 编辑边界：赛季/类型/我方主客创建后不可改；名额不得低于已确认人数（MATCH-16、P-04）。
- 状态控制：管理员可提前设为锁定，视为手动覆盖并停止自动流转；管理员可将任意比赛重置为任意状态（含回退与终态恢复，MATCH-06、DQ-08、DX-02）。
- 名额展示：总名额为正式 + 外挂的展示合计，分池限制不变（DQ-06）。
- 比分展示归本模块；比分录入/修正由 M06 按事件/比分权限控制（MATCH-11、DQ-07）。
- 赛程、比赛详情、分享链接（MATCH-09/12/13）。

**主要实体**：比赛。

**依赖**：报名、考勤、事件、阵容、分组；通知与审计。

**原型对应**：`matches.html`、`match.html`、后台“比赛管理”；完整（分享为复制链接）。

### 4.5 M04 报名与候补

**职责**：管理比赛名额、报名记录、候补队列与自动递补。

**关键功能**

- 资格：正常状态账号；比赛为报名中、未到截止、未开赛；不可重复报名（REG-01/09）。
- 分池容量：正式默认 30、外挂 4、候补 2（仅正式、全场合计）；比赛可覆盖；配置只影响新建比赛（REG-02/12、CONFIG-01/02）。
- 先到先得；正式满进候补；外挂满直接拒绝（REG-04/05）。
- 取消：报名截止后仍可自行取消；锁定后仅管理员可移除（REG-05/06/07）。
- 管理员移除已确认报名触发同池最早候补递补，并通知递补者（REG-07、NOTIFY-01）。
- 可见性：正式球员与管理员可看全队报名，外挂只看自己（REG-11）。
- 我的报名：进行中/历史两组，保留取消、移除与作废记录（REG-03）。

**主要实体**：报名。

**依赖**：比赛、球员档案、通知；被考勤、阵容、分组消费。

**原型对应**：`match.html`、后台“报名/考勤”；完整。

### 4.6 M05 考勤与签到

**职责**：记录比赛到场情况，支持自助签到与管理端修正。

**关键功能**

- 自助签到：仅已确认报名球员；窗口为开赛前 4 小时至比赛当天 23:59（ATT-01/02）。
- 考勤状态：正常、缺勤、临时到场；来源为自签、管理员标记、系统判定（ATT-03/04）。
- 管理员可标记/修正任意球员（ATT-05）。
- 临时到场：未报名到场；不占名额、计入出场、不计缺勤（ATT-06）。
- 缺勤：比赛结束 +6 小时仍未签到自动记缺勤，管理员可改（ATT-07）。
- 可见性：正式球员与管理员可看全队，外挂只看自己（ATT-08）。
- 取消的比赛不记考勤（§8.12）。

**主要实体**：考勤。

**依赖**：比赛、报名。

**原型对应**：`match.html`、后台“报名/考勤”；完整（出场统计未联动，原型限制）。

### 4.7 M06 事件与比分

**职责**：记录比赛过程，形成时间线、比分与球员统计来源。

**关键功能**

- 事件类型：进球、乌龙、换人、黄牌、红牌；点球是进球上的标记（EVENT-01/04）。
- 必填字段：分钟（1–120）+ 半场；事件归属主/客队（EVENT-11/12）。
- 类型专属字段：仅进球可带助攻；仅换人可填换上/换下（EVENT-02/03/14）。
- 权限：球员可创建/修改自己的事件（赛后 24 小时，换人除外）；管理员可增改任意；删除仅管理员；队内赛/训练赛球员可为主/客队任意球员录入（EVENT-06/07/08、§6.6 规则 5）。
- 分组限制：有分组时主队（橙队）事件只能选择橙队分组成员，客队（兰队）只能选择兰队分组成员（EVENT-12）。
- 软删除，修改与删除留痕（EVENT-09）。
- 时间线：上半场→下半场、分钟升序、同分钟进球优先；主队左侧、客队右侧（EVENT-13/15）。
- 比分：与事件独立录入；不一致仅提示不阻断；乌龙球比分记给对方（EVENT-10、§8.13）。
- 比分权限：比分录入与修正由 `event:edit:any` 控制；比赛编辑权限不承担比分修正（DQ-07）。
- 统计来源：出场由考勤（正常/临时到场）汇总，进球/助攻由事件汇总；由横切 `stats` 汇总任务每 10 分钟写入球员统计汇总表并刷新缓存，供分组自动分与球员/球队展示读取（DQ-10）。
- 统计口径：乌龙不计个人进球；取消比赛不计出场/进球/助攻；临时到场计出场（DX-01）。

**主要实体**：比赛事件、事件历史。

**依赖**：比赛、球员档案、报名名单；向分组自动分与统计提供进球/助攻数据。

**原型对应**：`match.html`、后台“事件/比分”；完整。

### 4.8 M07 阵容与战术

**职责**：管理某场比赛双方的阵型、首发与替补。

**关键功能**

- 权限：仅管理员编辑；正式球员只读；外挂与访客不可查看（LINEUP-01）。
- 阵型：8 套预置；自定义模板为复制预置并命名（LINEUP-02/03）。
- 阵容：首发 8 人 + 替补；新建阵容时首发为空、可排球员默认进入替补，首发需管理员拖拽 8 人到位；替补可显式加入/移出（LINEUP-04）。
- 我方/对手方：按 `ourSide` 判定；对外比赛对手方仅记录阵型与占位槽位，不录入球员（LINEUP-05）。
- 队内/训练赛：可排主队/客队双方球员（LINEUP-06）；阵容页展示本场报名球员并按分组两列，点击队伍切换阵容；生成分组后，橙队阵容只能使用橙队分组成员，兰队只能使用兰队分组成员，跨队拖拽/保存拒绝；可排球员还需为本场 CONFIRMED 且账号 ACTIVE 的报名，旧分组中的取消/注销球员自动排除。
- 名单一致性：分组名单与当前报名不一致时提示新增/移除球员并引导重新分组；未分组球员标注“未分组（无法排入阵容）”，不进入首发/替补；首发为 0 时提示从替补拖拽 8 人。
- 交互：拖拽或点击安排，换阵型需确认（LINEUP-07）。
- 版本：保存时校验版本，多人同时编辑拒绝覆盖；另存模板不改变本场阵容（LINEUP-08）。

**主要实体**：阵容、阵型模板。

**依赖**：比赛、报名/分组名单。

**原型对应**：`match.html`、后台“阵容”；完整。

### 4.9 M08 队内分组

**职责**：把队内赛/训练赛的报名名单分成水平与位置均衡的两队。

**关键功能**

- 时机：仅锁定状态可生成、调整、保存；其他状态分组只读且入口禁用（GROUP-11、§8.10）。
- 候选：本场报名名单；外挂是否参与按本场开关（GROUP-01）。
- 报名展示与清除：展示本场所有确认报名球员（球队球员/外挂）；提供“清除分组”，清除后可重新生成（GROUP-12）。
- 权重：手动 70% + 自动 30%，全局可配；自动分出场率/场均进球/场均助攻默认 50/25/25，可在系统设置调整；修改只影响后续生成（GROUP-02/03、DQ-02）。
- 缺失处理：两者都缺默认 3 星；少于最少出场（默认 3 场，可配置）优先手动分（GROUP-04）。
- 算法：门将/位置蛇形分配 + 局部搜索 + 随机因子/随机重启，目标总分差最小；相同名单连续重新生成不应总是同一结果（GROUP-06）。
- 均衡校验：人数差 ≤1、有 ≥2 名门将时每队至少 1 名、位置差尽量 ≤1；0/1 名门将只提示不阻断；不满足时警告，管理员二次确认后可保存（GROUP-05、§8.16；P-06 已确认）。
- 手动调整：拖拽、实时总分差与位置分布（GROUP-07）。
- 保存：写入快照；名单变化提示重新生成但不自动重算（GROUP-08/09/10）。

**主要实体**：分组。

**依赖**：比赛、报名名单、球员档案与事件统计、比赛状态。

**原型对应**：后台“队内分组”、`match.html` 分组只读；完整。

- 已读/未读（NOTIFY-03）。
- 公众号模板消息为二期（NOTIFY-04）。
- 通知内容不含手机号等敏感信息（§6.9）。
- 频次：实时逐条发送，不做聚合与免打扰；只覆盖需求列出的必要触发（NOTIFY-05、DQ-12）。

**主要实体**：通知。

**依赖**：各业务模块的写操作、用户；不反向依赖业务模块。

## 6. 核心业务流程

### 6.1 入队与授权

1. 访客自助注册 → 账号待审核。
2. 管理员审核通过 → 激活账号，默认 GUEST；需要时再由管理员转正为 PLAYER（P-03 已确认）。
3. 或使用入队邀请注册 → 免审直接入队（PLAYER）。
4. 管理员可随时调整角色；权限取多角色并集。
5. 注销后不可登录，历史数据保留。

### 6.2 比赛组织主链路

1. 管理员建赛（类型、时间、场地、名额、赛事字段）→ 状态“报名中”。
2. 生成分享链接/站内通知 → 球员可达。
3. 球员报名：名额未满为确认；正式名额满进候补；外挂满拒绝。
4. 到达报名截止（当天 00:00）→ 停止新增；到达锁定（当天 10:00）→ 停止球员自行取消。
5. 队内赛/训练赛：锁定后生成分组 → 排阵容。
6. 开赛前 4 小时开放签到；比赛开始 → 进行中。
7. 录入事件（进球/助攻/换人/牌）与比分 → 时间线更新。
8. 比赛结束 → 已结束；结束 +6 小时未签到自动记缺勤。
9. 数据沉淀到球员统计（二期排行榜/身价的数据来源）。

### 6.3 报名、候补与递补

- 报名 → 分池判断 → 确认 / 候补 / 拒绝。
- 球员取消（截止/锁定前）或管理员移除已确认报名。
- 同池最早候补自动转为已确认。
- 通知递补者；审计记录移除与递补。

### 6.4 签到与缺勤

- 已确认报名 → 开赛前 4 小时至当天 23:59 可签到 → 正常。
- 管理员可标记正常/缺勤/临时到场，并可修正。
- 比赛结束 +6 小时仍未签到 → 系统记缺勤。
- 未报名到场 → 管理员补录临时到场（不占名额、不计缺勤）。

### 6.5 事件与比分

- 录入事件 → 校验类型与专属字段 → 写入时间线。
- 事件推导比分（乌龙记对方）→ 与独立比分比对，不一致提示。
- 修改/删除事件 → 软删除并留痕。
- 进球/助攻数据 → 球员统计 → 分组自动分输入。

### 6.6 阵容

- 选择阵型 → 安排首发 8 人与替补。
- 我方/对手方分别设置；对手方仅记录阵型与占位。
- 保存阵容 → 版本校验 → 冲突则拒绝覆盖。
- 另存模板只写模板目录，不改变本场阵容。

### 6.7 队内分组

- 锁定后 → 读取报名名单（含外挂开关）。
- 计算手动分与自动分 → 生成两队 → 位置/门将均衡校验。
- 管理员拖拽调整 → 实时总分差与位置分布。
- 保存快照与名单指纹；名单变化提示重新生成，不自动重算。

### 6.8 延期与取消

- 延期：管理员改时间 → 重算截止/锁定 → 状态置为已延期 → 通知已报名者；重新排期后回报名中并恢复自动流转。
- 取消：状态已取消 → 报名作废 → 通知 → 不计考勤、不可再编辑赛况。

### 6.9 注销球员

- 管理员注销 → 账号不可登录 → 不进入球队页与报名名单。
- 未开赛比赛的报名自动取消并递补；历史数据保留。
- 通知本人并记录审计。
