## 1. 说明

- C 端接口在 `/api/v1/c/**`，B 端在 `/api/v1/b/**`；路径前缀同时决定会话命名空间（`YHFC_C` / `YHFC_B`）。
- 响应字段使用 camelCase，与数据库 snake_case 字段一一对应；计算字段（如 `confirmedCount`）由查询派生，不新增数据库字段。
- 数据库枚举存 TINYINT 数字；API 响应同时返回数字 code 与 `<field>Label` 大写字符串（如 `status=0`、`statusLabel="SIGNUP_OPEN"`），请求只接受数字 code，Label 只读；映射见 04 §2.4。
- 时间使用 ISO-8601 带时区偏移，统一输出 `+08:00`，例如 `2026-11-12T20:00:00+08:00`；请求参数同时接受 `Z` 与 `+08:00`。
- 本文的接口 ID（如 `AUTH-10`、`MAT-02`）与需求文档的需求 ID（如 `AUTH-01`、`MATCH-01`）是两套独立编号，前缀相同不代表同一编号；`PLAYER-*` 需求对应本文 `PLR-*` 接口。
- 分享链接（需求 MATCH-13、NOTIFY-02）由前端基于 `/matches/{id}` 生成并复制，不新增分享接口。

## 2. 通用约定

### 2.1 统一响应

成功与失败使用同一 envelope，`code` 为数字：

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "requestId": "req-7f3c..."
}
```

失败示例：

```json
{
  "code": 40001,
  "message": "参数校验失败",
  "data": {
    "details": [
      { "field": "jersey", "message": "号码已被占用" }
    ]
  },
  "requestId": "req-7f3c..."
}
```

- `code=0` 成功；其余为业务错误码。下文用错误名称指代对应数字码，响应返回数字。
- HTTP 状态码表达类别：200/201、400、401、403、404、405、409、415、422、429、500；HTTP 状态在响应行表达，body 只含 `code/message/data/requestId`，两者必须一致。
- `requestId` 由服务端生成并回写响应头 `X-Request-Id`。

### 2.2 分页

请求：`page`（默认 1，≥1）、`pageSize`（默认 10，可选 20/50/100）；比赛列表（MAT-02/09）因首页与 B01 预览需要，额外允许 1–100。
响应 `data`：

不分页例外：角色列表（ROL-01）、权限目录（ROL-06）、阵型模板（LIN-05）、事件时间线（EVT-01）、球队统计（STA-01）、赛季选项（MAT-13、MAT-14）返回 `{items}`（EVT-01 另含 `derivedScore`，STA-01 另含 `season`），排行榜（STA-03）返回 `{season,scope,items}`；PLR-01 使用 `limit/all` 的位置分组预览例外。其余列表统一使用下述 `Page` 结构。`Page<T>` 为逻辑分页类型，序列化为 `items/total/page/pageSize/totalPages`；Java 实现用 `PageResponse<T>` 包装 MyBatis-Plus `Page<T>`。

```json
{
  "items": [],
  "total": 0,
  "page": 1,
  "pageSize": 10,
  "totalPages": 0
}
```

### 2.4 认证、会话与 CSRF

- C/B 端分别使用 `YHFC_C`、`YHFC_B` 会话 Cookie；`HttpOnly`、`SameSite=Lax`，生产 `Secure`。
- 登录前调用 `GET /api/v1/{c|b}/auth/csrf`，token 在响应体，不使用 CSRF Cookie；写请求携带 `X-XSRF-TOKEN`。
- 登录成功后轮换 Session ID 与 CSRF token；登出/过期后重新获取。
- 微信小程序登录：AUTH-20 用 `wx.login` 的 `code` 换 openid；未绑定手机号时签发 10 分钟、一次性 `bindTicket`（Redis 只存 `sha256(ticket)`），AUTH-21 凭票据 + 短信码完成绑定并建立会话。两条接口免 CSRF；不使用 `redirect`/`state`，不返回 openid 或 `session_key`。
- 小程序端不依赖网络栈自动管理 Cookie：客户端维护内存 Cookie jar，从 `Set-Cookie` 提取 `YHFC_C`，后续请求手动携带 `Cookie` 头；CSRF 仍按会话校验。Phase 0 spike 已验证（`.scratch/miniprogram-login/spike.md`）。
- C→B 免登录：C 端会话调用 AUTH-18 签发 60 秒、一次性的票据（Redis 只存哈希），浏览器把票据放在 `/admin/` URL fragment（`#ticket=`，不进入服务端日志与 Referer）；B 端 AUTH-19 消费票据并复核后台权限后建立独立 `YHFC_B` 会话。两套会话仍独立过期（7 天/2 小时），票据本身不构成会话；兑换后前端立即替换 URL 清除 fragment，日志与错误响应不包含票据。
- 待审核（PENDING）允许公开读、C 端登录/登出（AUTH-04/05）、AUTH-01/14、AUTH-10、AUTH-02/03/06/20/21、INV-01/02、PLR-03、FIL-01、NTF-01~04（只读与标记已读）；其他写接口返回 `ACCOUNT_PENDING`（40303）。账号状态判断优先于角色权限；PENDING 创建时分配 GUEST 角色（P-03 已确认）。B 端登录仍需后台权限，PENDING 不具备。
- 注销（DISABLED）不可登录，不可通过邀请、小程序或手机号找回重新激活。

### 2.5 权限

- 权限码格式统一为三段式 `资源:动作:范围`；需求文档中的 `role:manage` 等为简写，落地时补全为 `role:manage:any`。服务端按权限码校验，B 端额外校验后台分区权限。
- 新增邀请权限点：`invite:manage:any`（管理员管理邀请）、`invite:create:match`（正式球员创建比赛邀请）。`match` 是对象范围例外，表示仅允许创建比赛邀请，不扩展通用 scope 枚举。
- 无权限访问返回 403；未登录返回 401；不要用 404 隐藏权限。

### 2.6 幂等与乐观锁

- 高风险写接口要求 `Idempotency-Key: <uuid>`：报名/取消/移除、考勤标记与补录、事件创建/修改/删除、比分、比赛创建/状态/延期/取消/重新排期、邀请创建/撤销、审核/转正/注销、阵容保存、分组生成/调整/保存/清除、设置修改、角色权限与用户角色分配。以各接口表的标注为准。
- 同一用户 + 接口 + 幂等键 + 相同请求哈希：返回首次结果；请求哈希不同返回 `IDEMPOTENCY_KEY_REUSED`。
- 阵容、比赛状态、事件修改请求体携带 `version`；不匹配返回 `VERSION_CONFLICT`。

### 2.7 限流、上传与文件

- 短信、登录、报名等关键接口按账号/IP 限流；超限 429，附 `Retry-After`。
- 小程序登录 AUTH-20 按 IP 30 次/分；AUTH-21 按手机号 + IP 10 次/分。
- 头像上传 `multipart/form-data`（字段 `file`）：服务端按文件头嗅探，仅接受 JPEG/PNG/WebP；文件字节上限 5MiB（5,242,880 字节）。空文件、损坏或超限返回 `40001`（`data.details` 指明原因），类型不符或伪装返回 `41501`；OSS 写入失败返回 `50001`。上传接口不限流。
- 上传只写入私有 OSS，不修改球员档案；响应返回 `{objectKey,signedUrl}`，绑定时把 `objectKey` 写入 PLR-03/PLR-06 的 `avatarUrl`。
- 签名 URL TTL 15 分钟，读接口按响应现签；Nginx `client_max_body_size` 为 6m（multipart 开销）。头像与场地环境图均以 5MiB 为准（P-107），两端均由应用层按端点校验，不依赖全局 multipart 上限。活动最多 10 张图，FIL-03 仍是单文件端点，前端按需连续调用。

### 2.8 枚举 code 与 label

- 数据库枚举存 TINYINT 数字；响应中每个枚举字段同时返回数字 `field` 与字符串 `fieldLabel`，例如 `status:0,statusLabel:"SIGNUP_OPEN"`。
- 请求体只接受数字 code；`*Label` 为只读派生字段，服务端忽略客户端传入的 Label。
- 字段映射见 04 §2.4；布尔字段（如 `active`、`manualStatus`、`includeGuests`）不生成 Label。
- 数组枚举字段返回 code 数组与对应 `*Labels` 数组，例如 `secondaryPositions` 与 `secondaryPositionLabels`。
- 下文业务规则中使用的大写枚举名（如 `SIGNUP_OPEN`、`CONFIRMED`）仅表示 `*Label` 语义，实际请求值使用对应数字 code。

## 4. 关键响应对象

所有对象字段使用 camelCase；敏感字段仅返回脱敏值，不返回 mp_openid（或历史 openid）、passwordHash、邀请 token。以下对象中的枚举字段按 §2.8 同时返回 code 与 `*Label`，不再逐项列出 Label 字段。

- `User`：`id,name,phoneMasked,status,roles,createdAt,wechatBound`；`name` 来自 `player.name`（1:1 档案），无档案时回退脱敏手机号；`wechatBound` 由 `mp_openid` 是否为空派生，始终返回布尔值，不返回 `mp_openid`。
- `UserSummary`：`id,name,phoneMasked,status,roles,type`（管理端）；`type` 来自 `player.type`。
- `TeamRef`：`id,name,shortName`。
- `Player`：`id,name,jersey?,type,position,secondaryPositions?,region?,avatarUrl?,skill`；`skill` 为 1.00–5.00 的两位小数 number。
- `Registration`：`id,playerId,type,status,registeredAt,cancelledAt?,active:boolean`（数据库 0/1 映射）。
- `Attendance`：`id,playerId,status,source,recordedAt`。
- `Score`：`scoreHome,scoreAway,derived?:DerivedScore`；`scoreHome/scoreAway` 为本次写入的兜底比分，`derived` 为计分事件推导值（EVT-05 成功时必无计分事件，恒为 null）。
- `Invite`：`id,type,team,matchId?,match?,inviter,expiresAt,maxUses?,usedCount,remainingUses?,status,exhausted?,createdAt`（不返回 token；创建响应中的 `inviteUrl` 只出现一次；`team` 为 TeamRef，`match` 为 MatchSummary，`inviter` 为 UserSummary）。
- `PlayerPublic`：`id,name,jersey?,position,secondaryPositions?,region?,avatarUrl?,skill,type,appearances?`；`skill` 为 1.00–5.00 的两位小数 number；仅正式且 ACTIVE；`appearances` 来自所选赛季统计汇总（缺省当前赛季）。
- `avatarUrl` 语义：**读响应**返回后端现签的 15 分钟 OSS 签名 URL；**写请求**（PLR-03/PLR-06）只接受 FIL-01/02 返回的 `objectKey`（`avatar/{userId}/{ulid}.{jpg|png|webp}`）。数据库与审计快照只存对象键，不含签名参数。
- `PlayerAdmin`：`PlayerPublic + userId,phoneMasked,status,admin,roles,createdAt,wechatBound`；`status` 来自 `app_user.status`，`roles` 来自 `user_role`，`admin` 表示拥有默认 `ADMIN` 角色或含 `role:manage:any` 权限的角色；`wechatBound` 同 `User`。无账号的球员 `userId/phoneMasked/status/statusLabel/createdAt` 均为 `null`，`roles` 为空数组，`wechatBound=false`；此类球员不可上传头像（FIL-02 依赖 `userId` 生成对象键），仍可编辑档案。
- `PlayerStats`：`playerId,season,appearances,goals,assists,updatedAt`。
- `MatchSummary`：`id,title,type,startAt,endAt,venue,round?,season,homeTeamName,awayTeamName,ourSide?,scoreHome?,scoreAway?,resultText?,status,totalMatchNo,seasonMatchNo,capacity,guestCapacity,waitlistCapacity,confirmedCount,guestCount,waitlistCount`；`scoreHome/scoreAway` 为最终比分（有计分事件取推导值，否则取兜底值）；`resultText` 为派生展示文本，`ourSide` 非空时按我方视角给出胜/负/平；`ourSide` 为 NULL（队内/训练）时不返回结果文本；无比分时为 null；三个名额字段与 MAT-03 同口径，供 C 端列表展示「已确认 / 名额」。
- `MatchDetail`：`MatchSummary + format,competition?,signupDeadline,cancelLock,version,derivedScore?:DerivedScore,myRegistration?:Registration`；`derivedScore` 仅在存在有效 GOAL/OWN_GOAL 时返回，否则为 null。
- `MatchAdmin`：`MatchDetail + includeGuests,manualStatus,statusUpdatedAt?,statusUpdatedBy?,createdBy,createdAt,updatedAt`。
- `MatchUpdate`：`title?,startAt?,endAt?,venue?,competition?,round?,season?,homeTeamName?,awayTeamName?,capacity?,guestCapacity?,waitlistCapacity?,includeGuests?,version`；类型/我方主客创建后不可改（P-04）；赛季可改，改赛季按新赛季重算 `seasonMatchNo`、`totalMatchNo` 不变（P-43）；兜底比分只通过 EVT-05 修改，且存在计分事件时不可修改。
- `MatchStatusUpdate`：`status,version,manualStatus?,reason?,startAt?,endAt?`；POSTPONED 需 `startAt/endAt`，CANCELLED 需 `reason`。
- `MyRegistration`：`registration:RegistrationRow,match:MatchSummary`。
- `RegistrationRow`：`id,player:{id,name,jersey?,position,skill},type,status,registeredAt,cancelledAt?`；`skill` 为 1.00–5.00 的两位小数星级。
- `AttendanceRow`：`id,player:{id,name,jersey?,position},status,source,recordedAt`。
- `Event`：`id,team,type,player?,assistPlayer?,inPlayer?,outPlayer?,minute,half,penalty,createdBy,updatedAt,version,deletedAt?`。
- `LineupView`：`side,formation,starters:[{slotKey,player?}],bench:[player]`。
- `LineupAdmin`：`LineupView + version,updatedAt,updatedBy?`。
- `GroupedPlayer`：`playerId,name,jersey?,position,manualScore?,autoScore?,finalScore?`；P-72 起新生成的 `manualScore` 与 `finalScore` 均为球员星级快照（1.00–5.00 两位小数），`autoScore` 为 null；历史分组行保留原值；由服务端写入，不接受客户端修改。
- `GroupingView`：`teams:{A:[GroupedPlayer],B:[GroupedPlayer]},diff,warnings,savedAt?`。
- `GroupingAdmin`：`GroupingView + scores:{A,B,diff},rosterFingerprint,generatedAt,savedAt?,ungroupedPlayerIds:[playerId],rosterDiff:{changed,addedPlayerIds:[playerId],removedPlayerIds:[playerId]}`。
- `Notification`：`id,type,typeLabel,title,body,refType?,refId?,readAt?,createdAt`；`type` 为数字 code，`typeLabel` 为大写字符串，映射见 04 §2.4（含报名成功、候补递补、创建/截止/锁定/开赛/结束、延期、取消、角色变更、审核通过、注销）；2–6 为预留编码，MVP 不产生。
- `AuditLog`：`id,actor:{id?,name?},action,targetType,targetId?,beforeRedacted?,afterRedacted?,requestId?,ipMasked?,createdAt,operatedAt?`；`createdAt` 为消费入库时间，`operatedAt` 为 Kafka 生产端写入的操作时间（旧数据/旧消息为空）；`actor` 为 `{id,name}` 对象（系统操作为 `id=null,name="系统"`）；快照返回脱敏后的 JSON 对象。脱敏递归对象/数组且键名不区分大小写：`phone` 保留前 3 后 4（长度 <7 为 `***`）；`mp_openid/openid/passwordHash/tokenHash/token` 替换为 `***`，非字符串值同样替换；`ipMasked` 对 IPv4 掩去最后一段、对 IPv6 保留前 3 组并追加 `::*`。`region`、`reason`、`avatarUrl` 不脱敏；`action/targetType` 不映射中文，由客户端按已知编码显示标签。
- `Settings`：`maxPlayers,maxGuests,maxWaitlist`；对应 `system_setting` 键为 `registration.maxPlayers/maxGuests/maxWaitlist`，`value_type=NUMBER`。
- `Role`：`id,code,name,isDefault,permissions:[string]`。
- `AdminTicket`：`ticket,expiresIn`；`ticket` 为 43 字符 Base64 URL，仅 AUTH-18 响应返回，不写入日志。
- `FormationTemplate`：`id,name,isPreset,baseTemplateId?,slots:[{slotKey,role,roleLabel,x(0–100),y(0–100)}]`。
- `TeamStats`：`{season,items:[PlayerStats]}`。
- `Leaderboard`：`{season,scope,items:[LeaderboardEntry]}`；`season` 在 `scope=all` 时为 `null`。
- `LeaderboardEntry`：`playerId,name,jersey?,position,positionLabel,avatarUrl?,appearances,goals,assists,ownGoals,internalAppearances,internalWins,winRate?,goalsPerMatch,assistsPerMatch,career?,history?`；`winRate` 为 0–100 百分比保留 1 位小数，分母为 0 时为 `null`；`goalsPerMatch/assistsPerMatch` 保留 2 位小数；`career/history` 在 `scope=season` 时为对象、`scope=all` 时为 `null`；排序与名次由前端按 02 §5.11 计算。
- `LeaderboardTotals`：`appearances,goals,assists,ownGoals,internalAppearances,internalWins,winRate?,goalsPerMatch,assistsPerMatch`；`career` 为当前赛季 + 历史累计（不晚于当前自然年），`history` 为早于当前自然年（不含当前赛季与未来赛季）；胜率与场均格式化规则同 `LeaderboardEntry`；无对应行补 0，胜率分母为 0 时为 `null`。
- `PromotionResult`：`{promotedPlayerId?,promoted:boolean}`。
- `DerivedScore`：`{scoreHome,scoreAway}`；由有效 GOAL/OWN_GOAL 事件推导，无计分事件时为 null。
- `GroupingSnapshot`：`{savedAt,rosterFingerprint,teams}`。
- 内部审计/排序字段：`cancelled_by`、`recorded_by`、`updated_by/deleted_by`、`match_grouping.created_by`、`system_setting.value_type/updated_by`、`app_user.last_login_at`、`invite_link.revoked_at`、`formation_slot/lineup_slot.sort_order` 仅用于落库、排序与审计，不进入客户端 DTO；`event_history` 只留存、不提供查询。
- `EventCreate` 必填：`type,team,minute(1–120),half`；换人填 `inPlayerId/outPlayerId` 且 `playerId` 为空；非换人填 `playerId`；助攻/点球仅 `GOAL`。球员创建限进行中或赛后 24h；队内/训练赛可为本场任意球员创建，对外比赛锁定本人所属队。球员/助攻/换上/换下须为本场 CONFIRMED 且账号 ACTIVE 的报名；有已保存分组时还须属于事件所属队分组（HOME=橙队=A 组、AWAY=兰队=B 组），OWN_GOAL 的球员按 `event.team` 校验、比分仍记给对方；分组不匹配返回 42203。
- `LineupSave` 必填：`formationTemplateId,starters,bench,version`；我方首发必须 8 人且 `playerId` 必填；对手方 `playerId` 可为空。
- `Settings` 数值均为整数：`maxPlayers 1–99`，`maxGuests/maxWaitlist 0–99`。

- `ActivitySummary` / `ActivityDetail` / `ActivityAdmin`：`id,title,type,typeLabel,startAt,endAt,signupDeadline,capacity,familyAllowed,costPerPerson,location,locationImageUrls,description,status,statusLabel,signupCount,signupOpen,version`；ACT-13 用详情的 `version` 作乐观锁；管理端额外返回 `locationImageKeys,createdBy`；登录时返回 `mySignup`。`locationImageUrls` 为按 `sort_no` 升序的 15 分钟签名 URL 数组（0–10 项），写请求与编辑/复制回填用 `locationImageKeys`（仅管理端，顺序与 URL 数组一致）；**详情与列表均不包含报名名单**。
- `ActivityCreate` / `ActivityUpdate`：`title,type,startAt,endAt,signupDeadline,capacity,familyAllowed,costPerPerson,location,locationImageKeys,description`；`familyAllowed` 创建必填，更新可部分；`locationImageKeys` 创建缺省为空数组，更新缺省保留原图、显式空数组清空、显式 null 返回 40001，最多 10 项且不可重复。
- `ActivitySignup` / `ActivitySignupRow`：`id,activityId,playerId,playerName,playerNo,avatarUrl,withFamily,familyNote,status,statusLabel,signedUpAt`。
- `LedgerEntry`：`id,type,typeLabel,categoryId,categoryName,categoryDirection,amount,description,occurredAt,playerId,playerName,activityId,activityTitle,version`；`amount` 为 JSON number、两位小数。
- `LedgerCategory`：`id,name,direction,directionLabel,sortNo,isActive,entryCount`；`direction` 为 `null` 表示通用分类。
- `LedgerSummary`：`income,expense,balance`；余额 = 收入 − 支出，金额均为 JSON number。

**后台权限判定**（P-98）

- 「后台权限」= 持有任一**非**个人自助权限；个人自助权限全量为 7 项：`activity:signup:own`、`attendance:checkin:own`、`event:create:own`、`event:edit:own`、`player:edit:own`、`registration:create:own`、`invite:create:match`。
- `AUTH-15`、`AUTH-18`、`AUTH-19` 与 `AUTH-17` 的「后台权限校验」均指本判定；账号状态判断（PENDING/DISABLED）优先于本判定。
- 正式球员默认持有 `attendance:view:any`、`lineup:view:any`、`grouping:view:any`、`ledger:view:any`，因此可进入 B 端并访问 `registrations`、`lineup`、`grouping`、`ledger` 四个只读分区；分区内写操作仍按各自权限码校验，权限不足返回 `40301`。
- **维护约定**：新增权限码必须显式归入「个人自助」或「后台」两类之一；未归类的权限码按后台权限处理。

PENDING 账号创建时分配 GUEST 角色，但写操作仍由账号状态白名单限制；审核只激活账号，不改变角色（见 P-03）。

## 6. 已确认的接口取舍

- `invite:manage:any` 加入权限种子；正式球员只使用 `invite:create:match`。
- 分组生成即持久化草稿，调整后 save 写快照。
