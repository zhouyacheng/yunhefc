# API 接口设计规范

## 1 目的与适用范围

本规范约束 `backend/` 的 HTTP API 设计、实现与维护，适用于 C 端 `/api/v1/c/**`、B 端 `/api/v1/b/**` 及后续新增接口。

设计依据：`docs/design/03.整体架构设计.md` 3.1、5；`docs/design/05.API接口设计.md`；`docs/rules/java-rules.md`。

一句话总纲：**路径稳定、响应统一、错误可识别、写接口幂等、C/B 权限边界清晰**。

---

## 2 路径与 HTTP 方法

1. 统一前缀 `/api/v1`；C 端 `/api/v1/c/**`，B 端 `/api/v1/b/**`。路径前缀决定会话命名空间（`YHFC_C` / `YHFC_B`），不依赖 Origin 判断。
2. 资源路径使用小写英文、复数名词，例如 `/matches`、`/matches/{id}/registrations`；状态迁移等非 CRUD 动作可使用明确的动作子路径（如 `/postpone`、`/cancel`、`/check-in`），不滥用动词，避免无意义缩写。
3. HTTP 方法表达明确语义：
   - `GET`：读取，不产生业务副作用。
   - `POST`：创建资源或执行非幂等动作。
   - `PUT`：整体替换资源（如保存完整阵容）。
   - `PATCH`：部分更新资源。
   - `DELETE`：删除或撤销资源。
4. 路径参数标识资源；查询参数用于筛选、排序、分页；请求体用于创建/更新数据。
5. 敏感信息（密码、令牌、验证码、openid）只放请求体或请求头，不放入 URL 查询参数。
6. 破坏性变更通过新版本表达，不直接改变既有接口语义。
7. API 文档的接口 ID（如 `MAT-12`）与需求 ID（如 `MATCH-12`）是两套编号；以 `05.API接口设计.md` 为准。

---

## 3 请求参数与校验

1. 每个接口在 05 中明确参数名、类型、必填性、默认值、格式与校验规则。
2. 服务端必须校验全部输入，不能依赖前端校验；Controller 使用 `@Valid` / `@Validated`。
3. 对字符串长度、数值范围、枚举值、日期格式、数组大小设置明确限制。
4. 枚举请求只接受数字 code；`*Label` 是只读派生字段，服务端忽略客户端传值。
5. 高风险写接口携带 `Idempotency-Key`：报名/取消、事件、比分、比赛状态、阵容、分组、审核/注销、邀请、设置、角色权限等。
6. 需要乐观锁的接口携带 `version`：阵容、比赛状态、事件修改；版本不匹配返回 `VERSION_CONFLICT`。
7. 认证写请求携带会话 Cookie，并通过 `X-XSRF-TOKEN` 提交 CSRF token；token 从登录或 `auth/csrf` 响应体获取，不使用 CSRF Cookie。
8. 文件上传使用 `multipart/form-data`；服务端校验类型与大小（头像上限 2MB），写入阿里云 OSS，业务表只存 URL。

---

## 4 统一响应格式

1. 成功与失败使用同一 envelope：

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "requestId": "req-7f3c..."
}
```

2. 成功固定 `code=0`；失败返回数字业务错误码 + 对应 HTTP 状态；HTTP 状态在响应行表达，body 不重复 `status` 字段。
3. 同类型接口字段命名、类型、可空性保持一致；响应只返回调用方需要的数据。
4. 不直接序列化实体或 Mapper 结果；统一转 DTO，避免泄露数据库内部字段。
5. 枚举字段同时返回数字 `field` 与 `fieldLabel` 字符串；请求只接受数字 code。
6. 时间统一 ISO-8601 UTC（如 `2026-11-12T12:00:00.000Z`）；业务边界先在 Asia/Shanghai 推导，再转 UTC。
7. 错误响应包含 `code`、`message`、`requestId`；不返回 SQL、堆栈、内部路径、密钥。

---

## 5 分页、筛选与排序

1. `page` 默认 1、≥1；`pageSize` 默认 10，可选 20/50/100。
2. 逻辑分页类型为 `Page<T>`，响应字段为 `items/total/page/pageSize/totalPages`；Java 使用 `PageResponse<T>` 包装 MyBatis-Plus `Page<T>`。
3. 小型只读集合（角色、权限、阵型模板、事件时间线、球队统计等）可在 05 中登记为不分页例外。
4. 筛选参数必须白名单化；排序字段必须走白名单，禁止 `${}` 拼接。
5. 分页排序必须有稳定 tie-breaker（如 `id`），避免翻页重复或遗漏。
6. 首页、球队页等组合场景由前端组合多个接口，不新增聚合接口，除非在 05 中明确。

---

## 6 HTTP 状态码与业务错误码

1. 使用合适的 HTTP 状态码：200/201、400、401、403、404、405、409、415、422、429、500。
2. 业务错误码稳定、可识别，统一在 05 §2.3 维护；错误响应包含错误码与 `requestId`，HTTP 状态由响应行表达。
3. 参数校验失败返回 `VALIDATION_FAILED`，`data.details` 给出字段与原因。
4. 未登录 401；无权限 403；资源不存在 404；状态/版本/唯一约束冲突 409；业务规则不满足 422；限流 429。
5. 不把所有错误都返回 HTTP 200；不只用 HTTP 200 判断业务成功。
6. 错误信息面向调用方，提供可处理信息，不泄露实现细节。

---

## 7 认证、CSRF 与权限

1. C/B 端分别使用 `YHFC_C` / `YHFC_B` 会话 Cookie；C 端滑动 7 天，B 端 2 小时，同一账号两端互不影响。
2. 登录前获取 CSRF token；登录成功后轮换 Session ID 与 CSRF token；登出/过期后重新获取。
3. 权限码统一 `资源:动作:范围`；服务端按权限码校验，B 端额外校验后台分区权限。
4. 待审核（PENDING）只允许公开读、登录/登出、AUTH-01/14、AUTH-10、短信/微信、邀请落地、自助资料/头像、通知只读与标记已读（NTF-01~04）；其他写接口返回 `ACCOUNT_PENDING`。
5. 未登录返回 401，无权限返回 403；不用 404 隐藏权限。
6. 前端路由守卫只做导航控制，真实权限必须由后端校验。

---

## 8 幂等、并发与版本

1. `Idempotency-Key` 由客户端生成 UUID；同一用户 + 接口 + 幂等键 + 相同请求哈希返回首次结果；请求哈希不同返回 `IDEMPOTENCY_KEY_REUSED`。
2. 幂等结果以 MySQL `idempotency_key` 为持久事实源；Redis 只做快速命中与并发占位。
3. 阵容、比赛状态、事件修改使用 `version` 条件更新；更新行数为 0 返回 `VERSION_CONFLICT`，并返回当前版本。
4. 报名名额以数据库条件更新/行锁为正确性保证；Redis 锁只削峰，不替代数据库约束。
5. 唯一约束冲突（报名、球衣号、场次编号、邀请 token 等）转换为明确业务错误码，不把 SQL 异常抛给前端。
6. 只对幂等接口自动重试；非幂等写请求不得盲目重试。

---

## 9 枚举、时间与数据格式

1. 数据库枚举存 TINYINT；API 返回 code + `*Label`，请求只接受 code；映射见 `04.数据库设计.md` §2.4。
2. 布尔字段使用 `true/false`；数据库 0/1；不生成 Label。
3. 时间使用 ISO-8601 UTC；日期筛选参数使用 `YYYY-MM-DD` 或 `YYYY-MM`，在 05 中明确。
4. ID 使用 JSON number 还是 string 由 05 统一；不得在不同接口间混用。
5. 金额/比例使用明确单位与精度；本期无账本接口，二期再定义。

---

## 10 文件、敏感数据与外部依赖

1. 头像上传经后端校验后写 OSS；响应返回业务 `url` 与短期 `signedUrl`，不返回 OSS 密钥。
2. 手机号只返回脱敏值；不返回 openid、passwordHash、邀请 token、会话 ID、CSRF token。
3. 日志与错误响应不得包含密码、验证码、token、openid、手机号明文。
4. 外部 HTTP 调用设置连接/读取超时与重试上限；失败返回明确业务错误。
5. CORS 只允许 `www` 与 `admin` Origin，允许携带凭证；不使用通配符。

---

## 11 审查清单

- [ ] 路径符合 `/api/v1/c|b/**`，资源名词复数、方法语义正确
- [ ] 请求参数有类型、必填、默认值、范围与格式校验
- [ ] 枚举请求只收数字 code，响应同时含 code 与 Label
- [ ] 成功 `code=0`，失败数字错误码 + 正确 HTTP 状态
- [ ] 响应只含 DTO，不泄露实体/数据库/敏感字段
- [ ] 列表使用 `Page<T>`/`PageResponse<T>`，例外已在 05 登记
- [ ] 筛选/排序白名单化，无 `${}` 拼接
- [ ] 高风险写接口有 `Idempotency-Key`
- [ ] 乐观锁接口有 `version`，冲突返回 409
- [ ] CSRF、会话、C/B 命名空间正确
- [ ] 权限码三段式，B 端分区权限已校验
- [ ] 时间 UTC，业务边界按 Asia/Shanghai 推导
- [ ] 文件上传校验类型/大小，OSS 私有 + 签名 URL
