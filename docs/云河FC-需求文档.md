## 2. 项目背景与目标

### 2.1 背景

云河FC 是一支业余足球队。当前球队运营依赖微信群接龙、Excel 和人工统计，存在以下问题：

- 比赛报名、候补、取消、考勤靠人工盯，容易漏人、超卖
- 比赛事件、比分、出场数据分散，难以沉淀为球员和球队数据
- 账本、动态、照片、视频、荣誉等资料分散，缺少统一入口
- 外挂球员、正式球员、管理员之间的权限边界不清晰
- 球队缺少一个对外的展示窗口

### 2.2 产品定位

**对内是运营工具，对外是展示窗口。**

- 对内：建赛、报名、分组、阵容、事件、考勤、数据、财务、内容、权限
- 对外：公开赛程、比分、球队页、动态、相册、视频、荣誉

### 2.3 业务目标

| 目标 | 说明 | 衡量方式 |
|---|---|---|
| 组织效率 | 报名、候补、分组、阵容、考勤、通知线上化 | 一场比赛的组织操作可在一个系统内完成 |
| 数据资产 | 比赛事件 → 球员/球队数据 → 排行榜/身价 | 赛季结束后可回溯每场事件和个人数据 |
| 财务透明 | 收支流水、分类统计、按人归集 | 月度/年度账本可查 |
| 内容传播 | 公众号、动态、相册、视频 | 球队内容可对外展示和分享 |
| 球队治理 | 角色、权限、操作日志、账号生命周期 | 关键操作可追溯，权限可配置 |

## 3. 用户与角色

### 3.1 访问者

| 角色 | 定义 | 核心诉求 |
|---|---|---|
| 未登录访客 | 未注册或未登录的公众 | 看赛程、比分、球队页、公开动态 |
| 外挂球员 | 临时参与球队比赛的外部球员 | 低门槛报名、看比赛信息、管理个人信息、后续转正 |
| 正式球员 | 球队正式成员 | 报名、看数据、录自己的事件、参与内容和投票 |
| 管理员 | 领队/队长/队务，本身通常也是正式球员 | 创建比赛、管理报名/考勤/阵容/分组、管理球员和权限、发布内容 |

### 3.2 身份状态与权限角色

系统把“身份”和“权限”分开：

- **身份状态**（单值）：外挂 / 正式 / 注销
- **权限角色**（可多个）：GUEST（外挂）、PLAYER（正式）、ADMIN（管理员），以及自定义角色
- **账号状态**（单值）：待审核 / 正常 / 注销

约束：

- 外挂与正式互斥，不能同时拥有。
- 管理员必须叠加在正式球员之上，不能是外挂管理员。
- 注销是账号状态，不是删除角色。
- 用户可以拥有多个权限角色，权限取并集。
- 默认角色不可删除；自定义角色可创建、编辑、删除（有用户拥有时不可删）。

### 3.3 典型场景

**正式球员**

1. 收到比赛分享/通知 → 打开比赛详情 → 看时间、地点、报名情况 → 报名
2. 赛前看阵容/分组 → 到场签到
3. 赛后看比分、事件、自己的数据（二期）→ 在 24h 内修正自己录入的事件
4. 看球队页、通知、参与投票/动态（二期）

**管理员**

1. 创建比赛 → 设置名额、报名截止、锁定 → 分享到微信群
2. 盯报名 → 处理候补递补 → 排阵容、做队内分组
3. 赛后录事件/比分 → 标记考勤 → 记场地费（二期）
4. 管理球员、角色权限、邀请链接、操作日志

**外挂球员**

1. 通过邀请链接注册 → 报名比赛
2. 看比赛信息、个人报名/考勤
3. 由管理员转为正式球员

**未登录访客**

1. 看首页、赛程、比分、球队页、公开动态
2. 点击报名时引导登录/注册

### 4.4 范围说明

- 本期只服务云河FC 一支球队；数据层可预留多队扩展，但不做多队功能。

## 5. 核心业务链路

```
管理员建赛 → 生成分享链接/通知 → 球员报名/进候补 → 报名截止/锁定
→ 队内分组/排阵容 → 比赛 → 录事件/比分 → 签到/考勤 → 数据沉淀（二期）
```

| 步骤 | 角色 | 关键动作 | 输出 |
|---|---|---|---|
| 建赛 | 管理员 | 填比赛信息、名额、截止/锁定时间 | 比赛进入“报名中” |
| 分享 | 管理员 | 生成分享链接，转发微信群 | 球员可达 |
| 报名 | 正式/外挂 | 报名或进候补 | 报名名单确定 |
| 锁定 | 系统/管理员 | 到达报名截止/锁定 | 名单锁定，候补可递补 |
| 分组/阵容 | 管理员 | 队内赛分组；排首发/替补 | 比赛阵容 |
| 比赛 | 球员/管理员 | 签到、记录事件/比分 | 比赛结果 |
| 考勤 | 球员/管理员 | 自签/管理员标记 | 出场与缺勤 |
| 数据 | 系统 | 汇总本赛季事件/考勤 | 分组评分与球员/球队展示 |

## 6. 功能需求

### 6.1 账号与权限

#### 目标

让正式球员、外挂球员、管理员以低门槛进入系统，同时保证身份、权限和账号状态清晰可控。

#### 需求清单

| ID | 需求 | 范围 | 说明 |
|---|---|---|---|
| AUTH-01 | 手机号+密码注册/登录 | ✅ MVP | 手机号唯一；密码 8–64 位，含字母和数字 |
| AUTH-02 | 短信验证码 | ✅ MVP | 注册/重置密码/绑手机；开发环境固定 123456；有频率限制 |
| AUTH-03 | 微信内网页授权 | ✅ MVP | 仅微信内浏览器；首次授权需绑定手机号；一个 openid 只绑一个手机号账号 |
| AUTH-04 | 开放注册 + 邀请注册 | ✅ MVP | 自助注册待审核，默认 GUEST；审核只激活账号；入队邀请注册免审为 PLAYER；比赛邀请只引导 |
| AUTH-05 | 账号状态 | ✅ MVP | 待审核/正常/注销；待审核可浏览、不可报名和互动；注销不可登录 |
| AUTH-06 | 密码重置与换绑 | ✅ MVP | 短信重置；管理员后台换绑手机号并留痕 |
| AUTH-07 | 未登录访客 | ✅ MVP | 可看公开内容；报名时引导登录/注册 |
| RBAC-01 | 权限点 | ✅ MVP | 格式 `资源:动作:范围`；系统预定义，管理员不能新增权限点；包含 `invite:create:match`（创建比赛邀请）、`invite:manage:any`（管理员管理邀请） |
| RBAC-02 | 多角色 | ✅ MVP | 用户可拥有多个角色，权限取并集 |
| RBAC-03 | 默认角色 | ✅ MVP | GUEST / PLAYER / ADMIN；ADMIN 必须叠加 PLAYER；GUEST 与 PLAYER 互斥 |
| RBAC-04 | 角色管理 | ✅ MVP | 角色 CRUD、权限勾选、用户分配、变更审计 |
| RBAC-05 | 角色保护 | ✅ MVP | 默认角色不可删、可改名；有用户拥有时不可删；至少一个 `role:manage` 用户 |
| RBAC-06 | 管理员自锁保护 | ✅ MVP | 最后一个拥有角色管理权限的用户不能被降权 |
| RBAC-07 | 注销 | ✅ MVP | 注销是账号状态，不删除历史数据 |

#### 业务规则

1. 手机号唯一；一个手机号只能注册一个账号。
2. 微信 openid 唯一；已绑定时直接登录该账号；换绑需先解绑，解绑仅管理员在后台操作，用户重新授权绑定，全程留痕。
3. 首次微信授权若未绑定手机号，必须先绑定手机号，不创建无手机号账号。
4. 待审核用户只能浏览公开内容、编辑个人资料；报名、签到、录事件、发动态等写操作禁止。
5. 注销用户不可登录；历史报名、事件、考勤等数据保留。
6. 邀请链接注册：入队邀请免审；比赛邀请只引导报名，不改变账号状态。入队邀请与邀请撤销仅管理员可操作；正式球员可创建比赛邀请。
7. 权限点目录由系统维护；管理员只能组合角色，不能创建新权限点。
8. 角色编码唯一；默认角色不可删除；自定义角色有用户拥有时不可删除。
9. 至少保留一个拥有 `role:manage` 权限的用户；服务端强制校验，不能只靠界面禁用。页面入口与操作按权限点判断，不按角色代码硬编码。
10. 角色/权限/用户角色变更必须留操作日志。

#### 验收要点

- 自助注册 → 待审核 → 管理员通过 → 可以报名。
- 邀请链接注册 → 直接正常 → 可以报名。
- 外挂与正式互斥；管理员必须同时拥有正式球员角色。
- 删除默认角色、删除仍被分配的角色被阻止。
- 最后一个管理员被降权时被阻止。
- 待审核用户报名、录事件、发动态被拒绝。

### 6.2 球员档案与球队页

#### 目标

建立统一、可展示、可统计的球员档案，并让球队页成为对外展示窗口。

#### 需求清单

| ID | 需求 | 范围 | 说明 |
|---|---|---|---|
| PLAYER-01 | 球员档案字段 | ✅ MVP | 姓名、球衣号、头像、地区、主位置、副位置 |
| PLAYER-02 | 位置枚举 | ✅ MVP | 前锋/中场/后卫/门将；1 个主位置 + 多个副位置 |
| PLAYER-03 | 外挂转正式 | ✅ MVP | 管理员操作；历史数据保留 |
| PLAYER-04 | 球员注销 | ✅ MVP | 状态改为注销；不删除历史数据 |
| PLAYER-05 | 头像 | ✅ MVP | 仅头像上传；比赛照片/视频二期 |
| PLAYER-06 | 星级 | ✅ MVP | 管理员设置 1–5 星；用于队内赛分组并对外展示 |
| PLAYER-07 | 自助资料 | ✅ MVP | 球员可编辑姓名、地区、主/副位置；号码、星级、角色由管理员维护 |
| TEAM-01 | 球队页排序 | ✅ MVP | 按位置分组展示（前锋 → 中场 → 后卫 → 门将）；每个位置组内按本赛季出场降序 → 号码升序 |
| TEAM-02 | 默认展示数量 | ✅ MVP | 每个位置组默认展示前 10 名，可“显示全部/收起”；任一组超过 10 人时提供切换 |
| TEAM-03 | 展示字段 | ✅ MVP | 姓名、号码、位置、地区、头像、星级；本赛季出场/进球/助攻来自统计汇总表，允许最多 10 分钟延迟 |
| TEAM-04 | 公开范围 | ✅ MVP | 匿名可见上述字段；手机号、考勤、账本、战术不公开 |
| TEAM-05 | 外挂是否展示 | ✅ MVP | 仅展示正式且正常状态的球员；外挂不进入球队页 |

#### 业务规则

1. 球衣号在正式球员中唯一；保存冲突时直接拒绝并要求修改，外挂不参与该唯一约束。
2. 注销球员不进入球队页、不可报名、不可被分组。
3. 外挂球员不进入球队页。
4. 公开页面不展示手机号、考勤、账本、战术。
5. 球队页展示星级；出场/进球/助攻来自统计汇总表，允许最多 10 分钟延迟，不要求逐次操作实时刷新。
6. 星级同时作为分组输入，并对外展示。
7. 球员可自助编辑姓名、地区、主/副位置；号码、星级和角色由管理员维护。

#### 验收要点

- 正式球员档案可维护，主/副位置合法；管理员可编辑姓名、号码、地区、位置、星级。
- 外挂转正后进入正式球员列表，历史数据保留。
- 注销球员不再出现在球队页和报名名单。
- 球队页按前锋/中场/后卫/门将分组展示；组内按本赛季出场降序、号码升序，每组默认前 10 名并可展开。
- 匿名访客能看到星级，但看不到手机号等隐私字段。

### 6.3 比赛管理

#### 目标

让管理员用一套标准流程完成比赛创建、状态流转、赛程展示和分享。

#### 需求清单

| ID | 需求 | 范围 | 说明 |
|---|---|---|---|
| MATCH-01 | 创建/编辑比赛 | ✅ MVP | 名称、开始/结束、场地、主队/客队、比分（可选，默认 0:0）、赛事/赛季（仅年份）/轮次、类型、赛制、总名额、外挂名额、候补上限、分组含外挂开关；报名截止/锁定由开始时间自动推导 |
| MATCH-02 | 比赛类型 | ✅ MVP | 正式、队内、训练、友谊 |
| MATCH-03 | 赛制 | ✅ MVP | 本期仅 8 人制；9/11 人制二期，数据模型预留扩展点 |
| MATCH-04 | 状态机 | ✅ MVP | 报名中 → 报名截止 → 锁定 → 进行中 → 已结束；分支：已取消、已延期 |
| MATCH-05 | 自动流转 | ✅ MVP | 按报名截止/开赛/结束时间自动切换；管理员可覆盖 |
| MATCH-06 | 管理员操作 | ✅ MVP | 关闭报名、延期、重新排期、取消、提前结束；状态下拉展示全部状态（含已延期/已取消）；管理员可将任意比赛重置为任意状态（含回退/终态恢复）；选择已延期进入延期流程，选择已取消进入取消原因流程 |
| MATCH-07 | 延期与重新排期 | ✅ MVP | 延期保留报名；按新时间重算截止/锁定；状态置为“已延期”；管理员重新排期后回“报名中” |
| MATCH-08 | 取消 | ✅ MVP | 保留报名记录但作废；通知；不计缺勤 |
| MATCH-09 | 赛程展示 | ✅ MVP | 主客队、时间、星期、轮次、比分、类型、胜负平、场次编号；比赛类型显示在地点左侧，场次编号在卡片右上；胜方名称红色背景 |
| MATCH-10 | 赛事字段 | ✅ MVP | 赛事名称/赛季/轮次为可选轻量字段；赛季仅四位年份；不做独立赛事和积分榜 |
| MATCH-11 | 比分 | ✅ MVP | 对外按主队/客队；队内按橙队/兰队（默认）；展示胜平负 |
| MATCH-12 | 比赛详情 | ✅ MVP | 状态、事件、比分；有事件时比分优先展示事件推导值；管理员可在详情直接修改状态；视频/B 站链接二期 |
| MATCH-13 | 分享链接 | ✅ MVP | 生成可分享链接，管理员转发微信群 |
| MATCH-14 | 未结束/未录比分提醒 | 🕒 二期 | 数据统计页提醒 |
| MATCH-15 | 场次编号 | ✅ MVP | 近期赛程每场显示“{年份}赛季第N场（累计M场）”；示例“2026赛季第57场（累计200场）”；新建比赛自动递增 |
| MATCH-16 | 编辑比赛 | ✅ MVP | 修改时间、场地、名额等赛程信息；比分修改归事件/比分权限（`event:edit:any`）；保留报名、事件、阵容和分组；赛季/类型/我方主客创建后不可改；正式/外挂名额分别不得低于对应已确认人数 |

#### 业务规则

1. 结束时间必须晚于开始时间，且开始与结束相差 2–4 小时；开赛时间必须晚于当天 10:00；报名截止自动等于开赛当天 00:00、锁定等于当天 10:00，不可单独修改。
2. 总名额为正式 + 外挂的展示合计（如 30+4），不单独作为报名门槛；正式/外挂仍按各自分池限制。总名额必须大于 0；外挂名额、候补上限不得小于 0；候补上限为全场合计，仅正式球员可用。
3. 报名截止停止新增报名；锁定停止球员自行取消，两者独立运算，但都由开始时间推导。
4. 队内赛无对手，主队/客队默认橙队/兰队；训练赛默认云河FC/训练组；对外比赛记录主队和客队名称，创建时显式选择我方主/客；未选择时按队名是否含“云河FC”推断；创建后赛季、类型、我方主/客不可修改。
5. 延期保留原报名，按新时间重算报名截止为当天 00:00、锁定为当天 10:00，状态置为“已延期”；管理员重新排期后回“报名中”。取消保留报名记录但不计考勤。
6. 已取消的比赛不能录事件/比分、不能签到。
7. 赛程“第 N 轮”为可空字段，不强制每场填写。
8. 比赛状态变更、延期、取消必须通知已报名者，并记录审计前后快照。
9. 创建比赛默认类型为队内赛；主队默认橙队、客队默认兰队；比赛名称默认橙队VS兰队；场地默认聚龙足球场；赛事默认空；赛季默认当前年份且仅允许四位年份；开始时间默认次日 20:00，结束为开始后 2 小时。
10. 近期赛程每场显示“{年份}赛季第N场（累计M场）”，按比赛日期顺序编号；新建比赛自动取同赛季最大值 +1、累计最大值 +1；示例“2026赛季第57场（累计200场）”。
11. 比分可在创建时录入，默认 0:0；也可赛后独立修改。
12. 比赛状态按报名截止、开赛、结束时间自动流转；管理员可提前手动设为锁定，手动修改后标记为手动并停止自动流转；管理员可手动重置为任意状态（含回退与终态恢复），重置后停止自动流转，可重新开启；已取消/已延期不自动覆盖；已延期需管理员重新排期后回到报名中。

#### 验收要点

- 管理员建赛后状态为“报名中”，分享链接可打开；比分默认 0:0。
- 到达报名截止/开赛/结束时间，状态自动流转；已取消/已延期不被覆盖；管理员手动修改后停止自动流转。
- 管理员可编辑比赛、强制关闭报名、延期、重新排期、取消、提前结束。
- 延期后报名保留，报名截止重算为开赛当天 00:00、锁定为当天 10:00，状态为“已延期”；重新排期后回“报名中”。
- 编辑比赛时赛季/类型/我方主客不可修改；名额调到低于已确认人数被拒绝。
- 创建/编辑/延期时开始时间早于或等于当天 10:00 被拒绝；开始/结束相差小于 2 小时或大于 4 小时被拒绝。
- 赛程正确显示主客队、时间、星期、轮次、比分、类型、胜负平，类型在地点左侧、场次编号在右上。
- 近期赛程显示“2026赛季第57场（累计200场）”格式；新建比赛自动递增。

### 6.4 报名与候补

#### 目标

让球员在有限名额下公平报名，超员自动进候补，取消后自动递补。

#### 需求清单

| ID | 需求 | 范围 | 说明 |
|---|---|---|---|
| REG-01 | 报名资格 | ✅ MVP | 比赛未开始、状态报名中、未过报名截止 |
| REG-02 | 分池 | ✅ MVP | 正式球员与外挂球员独立名额；候补只对正式球员开放，全场合计上限 |
| REG-03 | 报名状态 | ✅ MVP | 已报名、候补、已取消、已移除 |
| REG-04 | 先到先得 | ✅ MVP | 未满确认；正式球员满进候补，候补全场合计达到上限后拒绝；外挂满额直接拒绝，无候补 |
| REG-05 | 取消 | ✅ MVP | 锁定前可自行取消；锁定后不可自行取消 |
| REG-06 | 管理员移除 | ✅ MVP | 可移除并触发候补递补 |
| REG-07 | 递补 | ✅ MVP | 同池最早候补 → 已报名；通知本人 |
| REG-08 | 截止与锁定 | ✅ MVP | 两个字段分别校验；由开始时间自动推导：报名截止为当天 00:00、锁定为当天 10:00 |
| REG-09 | 重复报名 | ✅ MVP | 同一比赛同一用户只能有一条有效报名 |
| REG-10 | 外挂报名 | ✅ MVP | 需登录账号；比赛邀请链接引导注册/报名 |
| REG-11 | 报名名单可见性 | ✅ MVP | 正式/管理员可看名单；外挂只看自己的报名 |
| REG-12 | 报名默认参数 | ✅ MVP | 正式球员上限 30、外挂上限 4、候补上限 2（仅正式球员，全场合计）；系统配置项，可在创建比赛时覆盖 |

#### 业务规则

1. 可报名 = 状态为报名中 + 未过报名截止 + 未开赛 + 未超名额（可进候补）。
2. 正式球员与外挂球员各自计算名额，不互相挤占；候补只对正式球员开放，全场合计上限；总名额仅作展示合计，不参与门槛判断。
3. 候补顺序按报名时间；有人取消/被移除时，同池最早候补自动递补。
4. 报名截止由开始时间自动推导为当天 00:00，锁定为当天 10:00，不单独配置。
5. 锁定后球员不可自行取消；管理员可移除，并触发递补。
6. 取消/移除不删除记录，保留审计。
7. 待审核、注销用户不可报名。
8. 比赛取消/延期时，报名状态保留，不自动清空。
9. 报名默认参数：正式球员上限 30、外挂上限 4、候补上限 2（仅正式球员，全场合计）；系统设置可改；创建比赛可覆盖。
10. 名额与候补都满时拒绝报名；修改配置只影响新建比赛。
11. 报名/取消按钮必须按状态、报名截止、锁定实时禁用并展示原因，不能只在提交后提示。

#### 验收要点

- 名额未满直接报名成功；正式球员名额满且候补未满进入候补；外挂名额满直接拒绝。
- 候补只对正式球员开放，外挂不可加入候补。
- 有人取消后，候补第一位自动递补并收到通知。
- 锁定后球员取消被拒绝；管理员移除可成功并递补。
- 外挂和正式球员名额互不挤占。
- 默认上限 30/4/2（候补仅正式球员、全场合计）；候补满 2 后，正式球员名额已满的报名被拒绝。
- 系统设置可修改默认值；新建比赛可覆盖；已创建比赛不受影响。
- 比赛已取消、已结束、已截止或已开赛时，报名按钮禁用并显示原因；超过锁定后取消按钮禁用。

### 6.5 考勤

#### 目标

用低成本方式记录“谁来了、谁没来”，为出场、缺勤榜（二期）提供数据。

#### 需求清单

| ID | 需求 | 范围 | 说明 |
|---|---|---|---|
| ATT-01 | 自助签到 | ✅ MVP | 开赛前 4 小时至比赛当天 23:59 |
| ATT-02 | 签到资格 | ✅ MVP | 仅已报名（确认）球员可自签 |
| ATT-03 | 考勤状态 | ✅ MVP | 正常、缺勤、临时到场 |
| ATT-04 | 来源 | ✅ MVP | 球员自签、管理员标记、系统判定 |
| ATT-05 | 管理员修正 | ✅ MVP | 可标记/修正任意用户 |
| ATT-06 | 临时到场 | ✅ MVP | 未报名到场；不占名额、计入出场、不计缺勤 |
| ATT-07 | 缺勤判定 | ✅ MVP | 比赛结束 +6h 未签到 → 缺勤；管理员可改 |
| ATT-08 | 考勤可见性 | ✅ MVP | 正式/管理员可看全队；外挂只看自己 |

#### 业务规则

1. 报名 + 到场 = 正常；报名 + 未到 = 缺勤；未报名 + 到场 = 临时到场。
2. 临时到场不占报名名额，计入出场，不计入缺勤/鸽子榜。
3. 考勤来源必须记录，便于追溯。
4. 取消的比赛不记考勤。
5. 签到采用信任制（点击签到），管理员可修正；后续可扩展二维码/定位。
6. 自助签到窗口默认为开赛前 4 小时至比赛当天 23:59；窗口外按钮禁用。
7. 缺勤判定时点为比赛结束 +6 小时；管理员可修正。

#### 验收要点

- 已报名球员在窗口内可签到；窗口外不可。
- 管理员可标记正常/缺勤/临时到场。
- 临时到场不占名额、不计缺勤。
- 取消的比赛不产生考勤记录。

### 6.6 事件与比分

#### 目标

记录比赛关键事件，形成球员数据（二期排行榜/身价）的基础，并保证可追溯。

#### 需求清单

| ID | 需求 | 范围 | 说明 |
|---|---|---|---|
| EVENT-01 | 事件类型 | ✅ MVP | 进球、乌龙、换人、红牌、黄牌；点球是进球上的标记，不是独立类型 |
| EVENT-02 | 助攻 | ✅ MVP | 进球事件可带助攻者 |
| EVENT-03 | 换人 | ✅ MVP | 记录换上/换下两名球员；仅换人事件可填写这两个字段；新增/修改/删除仅管理员 |
| EVENT-04 | 点球 | ✅ MVP | 进球事件的点球标记；计入进球与比分 |
| EVENT-05 | 乌龙 | ✅ MVP | 我方球员，比分记给对方 |
| EVENT-06 | 球员录入 | ✅ MVP | 球员可创建/修改自己的事件，赛后 24 小时内；队内赛/训练赛可为主队/客队任意球员添加事件；换人事件仅管理员可新增/修改/删除 |
| EVENT-07 | 管理员权限 | ✅ MVP | 可改/删任意事件，不受时间限制 |
| EVENT-08 | 删除 | ✅ MVP | 仅管理员可删除 |
| EVENT-09 | 留痕 | ✅ MVP | 所有创建/修改/删除保留历史 |
| EVENT-10 | 比分独立 | ✅ MVP | 比分与事件独立录入；不一致提示，不阻止 |
| EVENT-11 | 事件时间 | ✅ MVP | 时间（分钟，1–120）与半场（上半场/下半场）均必填；半场默认上半场；显示为“上半场 23'” |
| EVENT-12 | 主队/客队 | ✅ MVP | 事件归属主队或客队；队内赛对应橙队/兰队；有分组时主队只能选橙队分组成员、客队只能选兰队分组成员；时间线按主队左/客队右排列 |
| EVENT-13 | 时间线排序 | ✅ MVP | 上半场优先下半场；同半场按分钟升序；同一分钟进球（含乌龙）优先 |
| EVENT-14 | 换人字段条件 | ✅ MVP | 仅换人事件显示/允许填写换上/换下；其他类型隐藏并禁用，不提交这两个字段 |
| EVENT-15 | 时间线布局 | ✅ MVP | 时间轴居中；主队事件在左侧，客队事件在右侧 |

#### 业务规则

1. 进球事件可带助攻；助攻只挂在进球事件上。
2. 换人事件必须同时记录换上和换下球员；只有换人事件显示/允许填写这两个字段，其他事件类型隐藏并禁用。
3. 点球是进球上的标记，点球进球计入进球数和比分。
4. 乌龙球单独类型：球员是我方球员，比分记给对方；乌龙不计入个人进球统计。
5. 球员只能操作自己作为主体的事件；换人事件仅管理员可新增、修改、删除，球员即使本人是换上/换下之一也不可操作。队内赛/训练赛例外：球员可为主队/客队任意球员添加事件。
6. 球员修改窗口为赛后 24 小时，以比赛结束时间为基准；管理员不受限。
7. 事件软删除，不物理删除；修改历史保留。
8. 比分与事件不做强制相等校验，只提示不一致。
9. 事件记录主队/客队；队内赛对应橙队/兰队；对外比赛球员录入时球队锁定为本人所属队，管理员可切换；队内赛球员可在主队/客队之间切换。有分组时，主队球员、助攻、换上/换下只能选择橙队分组成员，客队只能选择兰队分组成员；无分组时选择本场确认报名球员；对手方无球员档案时显示为空。
10. 事件必须记录时间（分钟）与半场；显示为“上半场 23'”；时间线按上半场→下半场、分钟升序、同分钟进球优先排列。
11. 比分推导按事件所属球队计算：主队进球记主队、主队乌龙记客队；客队反之。
12. 事件时间线以时间轴居中：主队事件在左侧，客队事件在右侧；按半场→分钟→进球优先从上到下排列。
13. 比分录入与修正由 `event:edit:any` 控制；比赛编辑权限只维护赛程信息，不修改比分。
14. 球员统计口径：出场由考勤（正常/临时到场）汇总，进球/助攻由事件汇总；乌龙不计个人进球；取消比赛不计出场/进球/助攻；临时到场计出场。

#### 验收要点

- 球员可录入自己的进球/助攻/牌；不能改他人的事件。
- 管理员可改/删任意事件。
- 超过 24 小时球员修改被拒绝。
- 换人必须有两个球员；点球计入进球；乌龙比分记给对方。
- 修改事件可在历史中查到。
- 事件录入必须选择时间（分钟）、半场和主队/客队；分钟为空时拒绝保存；只有换人事件显示并允许填写换上/换下。
- 删除事件后时间线与事件推导比分不再计入，但原始记录仍在数据中可追溯。
- 时间线按上半场→下半场、分钟升序；同一分钟进球优先于其他事件。
- 球员端事件弹窗没有“换人”选项，换上/换下始终不可见。
- 事件时间线主队事件在左侧、客队事件在右侧，时间轴居中。

### 6.8 队内赛分组

#### 目标

在队内赛/训练赛中把球员分成两队，尽量做到水平均衡、位置合理。

#### 需求清单

| ID | 需求 | 范围 | 说明 |
|---|---|---|---|
| GROUP-01 | 分组输入 | ✅ MVP | 本场报名/加入名单；外挂按每场开关决定是否参与 |
| GROUP-02 | 权重 | ✅ MVP | 手动 1–5 星 70% + 本赛季自动分 30%；全局可配 |
| GROUP-03 | 自动分 | ✅ MVP | 本赛季出场率（分母=已结束且未取消的球队比赛数）+ 场均进球 + 场均助攻，在本场候选池内归一化 |
| GROUP-04 | 缺失默认 | ✅ MVP | 两者都缺失默认 3 星；少于最少出场（默认 3 场，可配置）优先手动分 |
| GROUP-05 | 均衡校验 | ✅ MVP | 人数均分；有 ≥2 名门将时每队至少 1 名，0/1 名只提示不阻断；位置尽量均衡；手动调整不满足时警告并需二次确认 |
| GROUP-06 | 生成算法 | ✅ MVP | 门将/位置蛇形分配 + 局部搜索 + 随机因子/随机重启；目标总分差最小；相同名单连续重新生成不应总是同一结果 |
| GROUP-07 | 手动调整 | ✅ MVP | 可拖拽；实时显示两队总分差和位置分布 |
| GROUP-08 | 保存后 | ✅ MVP | 不随报名变化自动重算；名单变化提示需重新生成 |
| GROUP-09 | 快照 | ✅ MVP | 保存分数快照，保证历史可解释 |
| GROUP-10 | 位置不足 | ✅ MVP | 提示管理员，不阻断 |
| GROUP-11 | 分组时机 | ✅ MVP | 仅比赛状态为“锁定”时可生成、调整和保存分组 |
| GROUP-12 | 报名展示与清除分组 | ✅ MVP | 展示本场所有确认报名球员（球队球员/外挂）信息；有分组时按结果分两列展示，未分组/不参与单独列出；提供“清除分组”，清除后可重新生成 |

#### 业务规则

1. 分组只用于队内赛/训练赛；对外比赛不分组。
2. 外挂是否参与分组由每场开关决定，默认开启。
3. 手动分由管理员设置；球员不可自评。
4. 自动分：出场率（分母=本赛季已结束且未取消的球队比赛数）+ 场均进球 + 场均助攻，在本场候选池内归一化到 1–5 星。
5. 手动与自动加权：默认 70/30；都缺失默认 3 星。
6. 均衡校验：两队人数差 ≤ 1；有 ≥2 名门将时每队至少 1 名；位置差尽量 ≤1。手动调整不满足时给出警告，管理员二次确认后可保存。
7. 自动生成后可拖拽调整；保存后不随报名变化自动重算。
8. 报名名单变化时提示“需重新生成”，但不自动改动已保存结果。
9. 位置不足时提示管理员，不阻断生成。
10. 仅锁定状态可生成、调整、保存分组；其他状态分组只读且入口禁用。
11. 自动分默认权重：出场率 50%、场均进球 25%、场均助攻 25%，在候选池内归一化；手动/自动默认 70/30，可在系统设置调整；少于最少出场（默认 3 场，可在系统设置调整）优先手动分。

#### 验收要点

- 比赛未锁定时不能生成/调整/保存分组；锁定后可生成两队。
- 两队人数差 ≤1；有 ≥2 名门将时每队至少 1 名，0/1 名只提示不阻断；不满足时警告，确认后可保存。
- 手动星级和自动分都影响结果；缺失默认 3 星。
- 生成后可拖拽调整，实时显示分数差。
- 报名名单变化后提示重新生成，已保存结果不变。

## 8. 关键业务规则

1. **单队**：本期只服务云河FC；不做多队入驻、平台超管、跨队隔离。
2. **公开可见**：姓名、号码、位置、地区、头像、星级公开；手机号、考勤、账本、战术不公开。
3. **待审核**：只能浏览公开内容、编辑个人资料；不能报名、签到、录事件、发动态。
4. **注销**：不可登录；历史数据保留；不进入球队页和报名名单。
5. **注册**：手机号唯一；自助注册待审并默认 GUEST，审核只激活账号，转正由管理员操作；入队邀请注册免审为 PLAYER；openid 唯一。
6. **角色**：外挂/正式互斥；管理员叠加正式；多角色权限取并集。
7. **默认角色**：不可删除；权限可调整；至少一个 `role:manage` 用户。
8. **比赛**：本期 8 人制；四类比赛；创建默认队内赛、主队橙队/客队兰队、名称橙队VS兰队、场地聚龙足球场、比分 0:0；开始/结束相差 2–4 小时；近期赛程显示年份赛季/累计场次并自动递增；状态自动流转 + 管理员手动覆盖；管理员可提前锁定，并可将比赛重置为任意状态；总名额为展示合计。
9. **报名**：正式/外挂分池；默认正式 30、外挂 4、候补 2（仅正式球员，全场合计）；总名额为正式+外挂展示合计，不参与门槛；先到先得；系统配置可改，创建比赛可覆盖；报名按钮按状态、截止、锁定禁用。
10. **两个时间**：报名截止停止新增；锁定停止球员自行取消；报名截止自动为当天 00:00，锁定为当天 10:00，独立校验。
11. **锁定后**：球员不可自行取消；管理员可移除并触发递补。
12. **考勤**：报名+到场=正常；报名+未到=缺勤；未报名+到场=临时到场；取消比赛不记考勤。
13. **事件**：类型专属字段；时间（分钟）+ 半场 + 主队/客队；只有换人事件可填换上/换下，且换人事件仅管理员可新增/修改/删除；时间线按半场→分钟→进球优先，主队左侧、客队右侧；队内赛球员和管理员可为主客队任意球员添加事件；球员赛后 24h 内可改自己的；管理员不限；删除仅管理员；全部留痕。
14. **比分**：与事件独立录入；不一致只提示，不阻止保存；比分录入/修正由 `event:edit:any` 控制；统计口径为乌龙不计个人进球、取消比赛不计出场/进球/助攻、临时到场计出场。
15. **阵容**：仅管理员编辑；首发 8 + 替补；比赛详情可分别设置我方/对手方阵容和阵型，对手方由 `ourSide` 判定并仅记录阵型与占位槽位；支持自定义阵型、替补增删和版本冲突提示。
16. **分组**：手动 70%/自动 30%；人数、门将、位置作为校验项，不满足时警告并可确认保存；保存后不自动重算。
17. **通知**：报名、递补、改期、取消必须触达；站内消息为 MVP 主渠道。
18. **邀请**：入队/比赛两类；默认 7 天、默认不限使用次数（可设上限）、记录邀请人；入队邀请仅管理员创建，比赛邀请管理员与正式球员可创建；不可混用。
19. **审计**：角色/权限变更、管理员操作、事件变更、邀请变更留痕；业务上全部保留，归档与清理策略归技术阶段。
20. **并发**：报名不超卖；候补递补不重复；同一用户同一比赛只有一条有效报名。
21. **待确认项不默认实现**：AI 身价公式、账本挂账、排行榜口径等未确认内容不进入 MVP；9/11 人制仅数据模型预留，不做界面。
22. **列表**：赛程与球员查询支持筛选 + 显式搜索；分页默认 10、可选 20/50/100。

## 11. 非功能需求

### 11.1 安全

- 密码加密存储；不在日志/接口返回中暴露密码、openid。
- 会话安全：HttpOnly、Secure（生产）、SameSite；状态变更请求需 CSRF 校验。
- 短信验证码：有效期、尝试次数、按手机号/IP 限流。
- 邀请链接：随机 token、有效期、使用次数、可撤销。
- 权限校验在服务端执行，不能只靠前端隐藏。
- 公开接口脱敏手机号；不返回敏感字段。
- 管理员自锁保护；默认角色保护。
- 关键操作审计：角色/权限、用户审核/注销、比赛状态、管理员移除报名、管理员标记考勤、事件变更、阵容/分组保存、邀请变更；业务上全部保留，归档与清理策略技术阶段确认。

### 11.2 性能

- 单队规模：几十到几百用户；核心操作（报名、签到、录事件）应在秒级完成。
- 报名并发不超卖；候补递补不重复。
- 列表分页；公开页面可缓存。
- 状态流转和通知异步处理，不阻塞主流程。

### 11.3 兼容性

- C 端移动优先，兼容微信内置浏览器。
- B 端 PC 优先，主流现代浏览器。
- 微信授权仅在微信内可用；微信外使用手机号+密码。

### 11.4 可用性

- 比赛状态自动流转；失败可重试。
- 数据保留：通知 90 天；已投递 Outbox 7 天；失效邀请 30 天；审计日志在线永久保留，每年导出 OSS 冷备。
- 通知可达；候补递补、改期、取消必须触达。
- 操作失败给出明确提示；关键操作可追溯。

### 11.5 合规

- 国内部署需完成 ICP 备案；微信网页授权与模板消息依赖服务号。
- 个人信息最小化：只收集运营必需字段；公开页面不展示手机号。
- 用户注销后保留必要历史数据，但不可登录。

## 12. 验收标准

### 12.1 账号与权限

1. 自助注册 → 待审核（默认 GUEST） → 管理员通过 → 可报名（外挂名额）；转正后按正式名额报名。
2. 邀请链接注册 → 直接正常 → 可报名。
3. 待审核用户报名/录事件/发动态被拒绝。
4. 外挂/正式互斥；管理员必须叠加正式。
5. 删除默认角色、删除有用户的角色被阻止。
6. 最后一个管理员被降权被阻止。
7. 角色权限变更可在操作日志中查到。

### 12.2 比赛与报名

8. 管理员建赛 → 分享链接 → 球员打开可报名。
9. 正式名额满 → 进候补；有人取消 → 候补第一位递补并收到通知；外挂满额直接拒绝。
10. 报名截止后停止新增；锁定后球员不能自行取消。
10a. 默认报名上限：正式 30、外挂 4、候补 2（仅正式球员，全场合计）；系统设置可改，创建比赛可覆盖；名额与候补都满时拒绝报名；外挂满额直接拒绝。
11. 管理员移除报名 → 触发递补。
12. 到达时间点，比赛状态自动流转；管理员可覆盖。
13. 延期保留报名、重算时间并置为“已延期”，重新排期后回“报名中”；取消保留记录、通知、不计考勤。
14. 赛程正确显示主客队、时间、星期、轮次、比分、类型、胜负平。
14a. 创建比赛默认队内赛；主队默认橙队、客队默认兰队；比赛名称默认橙队VS兰队。
14b. 近期赛程显示“2026赛季第57场（累计200场）”格式；新建比赛自动递增。
14c. 创建比赛开始/结束相差小于 2 小时或大于 4 小时被拒绝；报名截止自动为开赛当天 0 点，锁定为当天 10 点。
14d. 创建比赛可选比分，默认 0:0；场地默认聚龙足球场；赛事默认空；赛季仅年份。
14e. 开赛时间必须晚于当天 10:00；创建后赛季/类型/我方主客不可改；名额低于已确认人数被拒绝。

### 12.3 考勤与事件

15. 已报名球员在窗口内可签到；窗口外不可。
16. 管理员可标记正常/缺勤/临时到场；临时到场不占名额、不计缺勤。
17. 球员可录自己的事件，24h 后不可改；管理员任意时间可改/删。
18. 换人需两名球员；点球计入进球；乌龙比分记给对方。
19. 事件修改留痕；比分与事件不一致有提示但不阻止。
19a. 事件录入必须选择时间（分钟）、半场和主队/客队；只有换人事件显示并允许填写换上/换下。
19b. 时间线按上半场→下半场、分钟升序；同一分钟进球优先于其他事件。
19c. 队内赛时，球员和管理员都可为主队/客队任意球员添加事件；对外比赛球员仍只录自己的事件。
19d. 球员端事件弹窗没有“换人”选项，换上/换下不可见；换人事件仅管理员可新增、修改、删除。
19e. 事件时间线主队事件在左侧、客队事件在右侧，时间轴居中。
19f. 分钟为空时拒绝保存；删除事件为软删除，时间线与推导比分不再计入，但原始记录保留。
19g. 有分组时，主队事件只能选择橙队分组成员，客队事件只能选择兰队分组成员；跨队选择/保存被拒绝。
19h. 管理员可在比赛详情直接修改比赛状态，成功后详情与后台同步；无需跳转后台页面。
19i. 比赛详情有事件时比分显示事件推导值；后台独立比分仍保留并用于差异提示。

### 12.4 阵容与分组

20. 管理员可选预置/自定义阵型并拖拽；球员只读。
21. 比赛详情可分别设置我方和对手方阵容/阵型；对手方由 `ourSide` 判定，仅记录阵型与占位槽位，不录入球员姓名。
22. 首发 8 + 替补；替补可加入/移出并持久化；并发保存触发版本冲突。
22a. 有分组时，橙队阵容只能拖拽/移动/保存橙队分组成员，兰队只能使用兰队分组成员；跨队操作被拒绝。
23. 队内赛可生成两队，人数差 ≤1；有 ≥2 名门将时每队至少 1 名（0/1 名只提示）。
24. 分组可手动拖拽，实时显示分数差；保存后不自动重算。
25. 名单变化提示重新生成。

### 12.5 通知与邀请

26. 报名成功、递补、改期、取消产生站内消息。
27. 入队邀请注册免审；比赛邀请只引导报名。
28. 邀请链接过期/次数用尽/撤销后不可用。

### 12.6 公开页面与审计

29. 匿名访客可看赛程、比分、球队页公开字段（含星级、默认前 10）；看不到手机号、考勤、账本、战术。
30. 操作日志可通过管理后台查询（MVP 后端已具备，界面后续完善）。
31. 赛程筛选（类型/地点/状态/年份/月份）点击搜索后生效；分页默认 10，可选 20/50/100。
32. 球员查询支持姓名/地区模糊搜索、类型/管理员/状态/位置/星级筛选，默认号码升序，支持分页。

## 15. 附录 B：术语表

| 术语 | 说明 |
|---|---|
| 外挂球员 | 临时参与球队比赛、未转为正式成员的球员 |
| 正式球员 | 球队正式成员，拥有完整球员权限 |
| 管理员 | 领队/队长/队务，拥有管理权限，通常也是正式球员 |
| 待审核 | 自助注册后等待管理员通过的账号状态 |
| 注销 | 账号停用状态；不是删除角色或历史数据 |
| 报名 | 球员表示参加某场比赛 |
| 候补 | 名额已满后的排队状态 |
| 递补 | 有人取消/被移除后，候补按顺序转为已报名 |
| 报名截止 | 停止新增报名的时间 |
| 锁定 | 停止球员自行取消的时间；与报名截止独立 |
| 临时到场 | 未报名但到场，由管理员补录 |
| 鸽子榜 | 二期缺勤统计榜单 |
| 身价 | 二期基于位置/出场/进球/助攻计算的球员价值（人民币） |
| 阵型 | 8 人制的场上位置分布，如 2-3-2 |
| 阵容 | 某场比赛的首发和替补安排 |
| 分组 | 队内赛/训练赛把球员分成橙队/兰队（主队/客队） |
| 事件 | 比赛中的进球、乌龙、换人、红黄牌、点球等 |
| 乌龙球 | 我方球员打进本方球门，比分记给对方 |
| 助攻 | 进球前的最后一传，挂在进球事件上 |
| 战术板 | 管理员拖拽球员排阵型的界面 |
| 分享链接 | 可转发到微信群的比赛/报名链接 |
| 邀请链接 | 入队或比赛报名的邀请凭证 |
| RBAC | 基于角色的访问控制 |
| 权限点 | 系统预定义的最小权限，格式 `资源:动作:范围` |
| MVP | 首版必须交付的范围 |

## 16. 附录 C：关键决策记录

| 租户 | 单队实现；数据层预留多队扩展，不做多队功能 |
