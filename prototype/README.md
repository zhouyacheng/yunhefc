# 云河FC 可交互页面原型

基于 `docs/云河FC-需求文档.md` 的纯前端交互原型。只演示交互与信息架构，不接服务端、不发送真实短信、不包含真实业务数据。

## 打开方式

推荐用本地静态服务（`file://` 也能打开，但 localStorage 行为在部分浏览器不一致）：

```bash
python3 -m http.server 4173 --directory prototype
```

然后访问：

- 首页：http://localhost:4173/index.html
- 赛程：http://localhost:4173/matches.html
- 比赛详情：http://localhost:4173/match.html?id=m1
- 球队页：http://localhost:4173/team.html
- 排行榜：http://localhost:4173/leaderboard.html
- 活动：http://localhost:4173/activity.html
- 动态与相册：http://localhost:4173/content.html
- 账本：http://localhost:4173/ledger.html
- 登录/注册：http://localhost:4173/login.html
- 个人中心：http://localhost:4173/profile.html
- 邀请落地：http://localhost:4173/invite.html?token=…
- 管理后台：http://localhost:4173/admin.html

## 演示身份

页面右下角的「演示身份」面板可切换：

| 身份 | 能做什么 |
|---|---|
| 未登录访客 | 浏览首页、赛程、比赛详情、球队页；报名时引导登录 |
| 待审核用户 | 只能浏览；报名/签到/录事件被拦截 |
| 外挂球员 | 报名、取消、签到、看公开内容；不能看战术/分组 |
| 正式球员 | 报名、签到、录自己的事件、查看阵容/分组 |
| 管理员 | 全部权限；含独立管理后台 |

快速登录账号（密码任意）：

- 管理员：`13800000000`
- 正式球员：`13900000001`
- 外挂球员：`13900000002`
- 待审核：`13900000021`

验证码固定 `123456`。

## 已覆盖的交互

### 公共 / 球员

- 首页最近一场比赛、报名 CTA、最近比赛、活动入口（访客可见）、账本入口（登录且非外挂）与动态入口（仅正式球员与管理员）、球队火力二期占位、二期能力占位（AI 身价、投票、资产与荣誉；公众号提醒占位卡已移除，P-172）
- 首页 hero 展示比赛类型、报名队列（仅正式）、外挂队列、候补队列
- 近期赛程显示场次编号：`2026赛季第57场（累计200场）`；类型在地点左侧，场次编号在右上
- 赛程支持比赛类型、地点、状态、月份、自定义时间筛选，条件变更即生效（地点输入防抖，无“搜索”按钮）；默认按开赛时间降序；分页默认 10 条，可选 20/50/100
- 赛程与首页近期赛程卡片展示报名人数与名额（正式 / 外挂 / 候补：已确认 / 名额上限），仅展示不可点击
- 比赛详情：概览（含报名）、事件、阵容、分组
- 报名 → 正式名额满进候补 → 取消 → 自动递补；候补仅正式球员，外挂满额直接拒绝；按钮按状态/截止/锁定禁用
- 签到：窗口为开赛前 4 小时至比赛当天 23:59，窗口外按钮禁用；比赛结束 6 小时后未签到自动记缺勤
- 正式球员/管理员可查看全队考勤；个人中心“我的报名”分进行中/历史，保留取消、移除与比赛作废记录
- 球员录入/修改自己的事件（赛后 24h 内）；队内赛/训练赛可为任意球员录入；管理员可录/改任意事件
- 事件记录：时间（分钟，必填）+ 上半场/下半场 + 主队/客队；选择球队后球员/助攻/换人下拉只显示该队球员；只有换人事件显示换上/换下，换上从替补、换下从首发选择，且换人事件仅管理员可新增/修改/删除；仅进行中/已结束比赛可录入；软删除保留记录；时间线按半场→分钟→进球优先排序；主队左侧、客队右侧
- 比赛详情可切换查看我方/对手方阵容和阵型；对手方由 `ourSide` 判定，仅阵型占位
- 邀请：比赛详情“邀请队友”生成比赛邀请；后台“邀请管理”创建入队/比赛邀请（创建成功弹窗复制链接）、撤销；`invite.html` 落地接受入队邀请或跳转比赛报名
- 球队页：按前锋/中场/后卫/门将四组展示；赛季下拉默认当前年份，选项为已有赛季 ∪ 当前年份；组内按所选赛季出场降序 → 号码升序并展示全部正式球员；展示星级（1.00–5.00 两位小数，按半星粒度渲染）与所选赛季统计（种子数据，允许最多 1 分钟延迟）；页头提供排行榜入口并沿用所选赛季
- 活动：活动列表（范围最近活动/已结束活动/全部 + 类型/状态/月份/自定义时间筛选，不提供历史范围；月份与自定义时间互斥、默认不筛选）与卡片；报名/取消、满员与截止禁用、已取消/已结束只显示徽标、分享复制链接；活动为独立实体，不复用比赛
- 动态与相册：时间线/相册双视图；发布纯文字或引用相册的动态、点赞/取消、删除本人动态、举报；新建相册、比赛/活动详情「照片」入口带 `matchId`/`activityId` 过滤、上传本地图片、删除本人照片、管理员设封面/删相册；未登录、待审核与外挂按可见性给出提示
- 排行榜：出场/进球/助攻/场均进球/场均助攻/胜率/乌龙 7 个榜单，默认出场；赛季切换，下拉不提供生涯累计；单赛季窗口固定展示历史累计（早于当前年份，不含当前赛季）与生涯累计（当前赛季+历史累计），均只显示当前榜单主指标；标准竞赛排名（1、1、3），同值按次级指标 → 号码升序；胜率只统计队内赛并按已保存分组判归属；入口在球队页页头
- 个人中心：资料、自助编辑姓名/地区/主副位置、头像上传/移除（本地压缩）、待审核提示、通知已读、我的报名、账号与安全（微信绑定状态为演示数据）、退出
- 登录/注册：演示账号、待审核注册、验证码提示；自行注册手机号可再次登录

### 管理员

- 比赛管理：创建/编辑比赛（默认队内赛、橙队/兰队、比分 0:0、场地聚龙足球场）；列表展示比赛开始/结束时间、赛季、场次；开赛必须晚于 01:00；类型/我方主客创建后不可改，赛季可改并重算赛季场次编号（累计场次不变）；场次留空默认同赛季下一场（新赛季首场为 1），编辑可清空；名额不得低于已确认人数；延期→已延期→重新排期；管理员可将任意比赛重置为任意状态（含回退/终态恢复），取消需填写原因；分页默认 10，可选 20/50/100
- 报名/考勤：默认选中时间最新的场次，比赛选择按时间降序并按赛季分组（正式实现支持赛季/月份范围/状态筛选、筛选后按结果校正选中与下拉分页）；正式/外挂分池、候补（仅正式球员）、移除并自动递补、正常/缺勤/临时到场、补录临时到场
- 系统设置：报名默认上限 30/4/2，新建比赛自动带入，创建时可覆盖
- 事件/比分：有进球/乌龙事件时比分按事件推导（只读），无计分事件时可录入比分；事件录入/编辑/软删除（分钟必填、半场、主队/客队）、审计前后快照；换人之外不显示换上/换下
- 阵容：选择比赛后展示本场报名球员，有分组时按橙队/兰队两列，点击队伍切换阵容；我方/对手方分别设置阵型和首发/替补；队内赛/训练赛有分组时，橙队只能使用橙队分组成员、兰队只能使用兰队分组成员，跨队拖拽/保存拒绝；8 套预置阵型 + 自定义模板、拖拽/点击换人、替补显式增删、版本冲突提示。对手方仅记录阵型与占位槽位
- 队内分组：仅比赛状态为“锁定”时可生成/调整/保存/清除；生成含随机因子，直接使用球员星级均衡，位置/门将均衡、拖拽调整、实时总分差与位置分布、名单变化提示、保存快照；分组页展示本场报名球员，有分组时按 A/B 两列展示
- 球员：姓名/号码/地区/位置/星级（1.00–5.00，两位小数）/头像编辑、9 档半星筛选、排序、分页；正式球衣号重复直接拒绝；审核只激活默认 GUEST、外挂转正经号码唯一校验、注销需填写原因（未开赛报名自动取消并递补）；微信列展示已绑定/未绑定（演示数据），仅已绑定显示解绑入口
- 角色权限：角色新建/重命名/删除、权限勾选（37 个权限码）、用户-角色分配、互斥和管理员保护
- 邀请管理：入队/比赛邀请创建、复制链接、撤销；默认 7 天、默认不限次数
- 操作日志：记录关键操作及其创建时间、操作时间，支持分页与变更前后详情

## 脚本结构

- `assets/js/core.js`：状态与迁移、鉴权、球员、注册表、场次编号、格式化、公共 UI
- `assets/js/match.js`：比赛生命周期、报名/候补、考勤
- `assets/js/events.js`：事件领域、时间线、共享事件弹窗
- `assets/js/lineup.js`：阵型、球场、阵容版本、替补
- `assets/js/grouping.js`：分组评分、生成、汇总、快照
- `assets/js/content.js`：动态与相册（时间线、相册、点赞、举报）演示交互
- `assets/js/public.js` / `assets/js/admin.js`：页面渲染与交互

## 数据与重置

- 初始数据在 `assets/js/data.js`
- 演示状态存在浏览器 `localStorage`，key：`yunhefc_prototype_v1`
- 点击「演示身份」面板里的「重置演示数据」可恢复初始状态
- 所有操作只影响本地浏览器，不会请求后端

## 原型限制

- 冲突检测只覆盖阵容版本；`save()` 写整个 localStorage，多标签页跨模块编辑仍可能互相覆盖。
- 阵容编辑直接改内存中的 lineup，未点“保存阵容”前若触发其他保存操作会被一并写入；正式实现需改为草稿副本，仅在提交时校验版本并落盘。
- 出场/进球/助攻为种子数据，考勤与事件不会自动回填统计；正式实现需按考勤与事件重算（临时到场计入出场）。排行榜的队内赛出场/胜场与乌龙为演示推导值，正式实现取自统计汇总表。
- 操作日志仅保留最近 120 条，超出截断；事件修改历史依赖该日志，正式实现需持久化完整历史。
- 比赛状态自动流转在页面加载时执行，长时间停留不会自动刷新。
- 场次编号按本地数据 max+1 生成，无并发锁。
- 自定义阵型只复制预置并命名，不支持拖拽修改坐标；另存模板只持久化模板目录，不改变本场阵容；需在阵型列表选择该模板并保存阵容后生效，版本冲突在保存阵容时校验。
- 筛选/分页状态保存在页面内存，刷新后回到默认值。
- 原型为演示简化：注册不保存密码，登录只匹配手机号、任意密码放行，密码规则仅做前端校验。正式系统需按 AUTH-01 保存密码哈希并校验。

## 原型专属能力

以下能力只用于演示，不属于正式需求：演示身份切换与快速登录、管理员一键进入、重置演示数据、首页球队火力二期占位。正式实现以需求文档为准。

## 未覆盖

二期模块只做占位说明：AI 身价、AI 天气、视频、投票、公众号模板消息、资产、荣誉、历史数据导入。活动、账本与动态/相册原型已覆盖（演示数据，不接后端）；动态与相册不含视频、评论、公开访问与分享链接。微信 OAuth、真实短信、真实权限校验不在原型范围内。
